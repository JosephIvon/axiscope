# 第6章 特征与归因

**本章承接**：第 5 章讲引擎的骨架。这一章讲引擎里**最难替代**的一段——
一条证据怎么变成一个置信度，以及一堆证据怎么变成一个排序。

**学完你会**：能手工复算 `S(e)` 与 `C(h)`，
能解释"缺席"为什么也要扣分、能封顶，
能说出反事实自检为什么必须 held-out。

**前置**：第 3 章（知识库）、第 5 章（引擎）。

**素材坐标**：`docs/kb/KB4-attribution-model.md`、`docs/contracts/C3-diagnosis.md`、
`docs/wiki/03-analysis-core.md`（锚点 `axiscope@3576c9c`）。

> **可验证主张**：单条证据的强度是一个**四因子乘积**：
> `S(e) = g(ρ) × conf(f) × n_factor(n/n_ref) × band_factor(f0)`
> （`docs/kb/KB4-attribution-model.md:319`），四个因子分别管
> **离阈值多远**、**这条特征本身有多可信**、**样本量够不够**、
> **这个频点有没有落在可靠频带里**。
> 聚合时支持度 `A_sup = 0.55·Smax + 0.45·Srest`
> （`docs/kb/KB4-attribution-model.md:363-369`），
> 反证扣分 `A_con = min(0.5, Σ v_j)`；
> 另加 **CAP 表 12 条封顶**（`docs/kb/KB4-attribution-model.md:496-507`）
> 与 **14 条全局不变式**（`docs/kb/KB4-attribution-model.md:17-36`）。
> 整个模型**只引用规则号，不自造阈值**（`docs/kb/KB4-attribution-model.md:9`）。

**已验算**：本章坐标按锚点 `axiscope@3576c9c` 读源文件，
由 `book/tools/audit_coords.py` 复核；§6.6 的两个算例在 KB4 里有逐格明细，
本章 §6.6.3 当场手算一遍。

## 6.1 概念：置信度必须能被手算

诊断报告里的每个 `confidence`，读者都会问同一个问题：
**这个 0.59 是怎么来的？**

如果答案是"模型算的"，读者就没法判断它可不可信——
他只能选择信或不信。而本仓的选择是：**让读者能自己算一遍**。

KB4 的 §0 摘要把三条工作原则放在最前面
（`docs/kb/KB4-attribution-model.md:9`、`:12-13`）：

- 本文**只引用规则号**，不自造阈值；
- **确定性铁律**：LLM 只能改写 `display_name`/`rationale`/`note`/`verdict.summary`
  的文字；`S`、`A_sup`、`A_con`、`C`、`rank`、`severity` **由规则引擎写入**。

"LLM 不得改数值"在 C3 规则 3 里也写了一遍
（`docs/contracts/C3-diagnosis.md:960`）——
契约与知识库**两处各写一遍**，是因为这是整个系统里最容易被绕过去的一条。

**手算可行**是这套模型的设计约束，不是副产品。
§6.6 的算例 A/B 就是为此存在的：KB4 把每一格中间量都列出来
（`docs/kb/KB4-attribution-model.md:379-467`），
读者可以拿计算器复核。

## 6.2 单条证据强度：四个因子

`S(e) = g(ρ) × conf(f) × n_factor(n/n_ref) × band_factor(f0) ∈ [0,1]`
（`docs/kb/KB4-attribution-model.md:319`）。

四个因子各管一件事：

### 6.2.1 `g(ρ)`：离阈值有多远

`g(ρ) = 0.5 + 0.5·min(1, log10(ρ)/log10(4))`
（`docs/kb/KB4-attribution-model.md:327`），其中 ρ 是实测值与阈值的比。

锚点表（`docs/kb/KB4-attribution-model.md:330`）：

| ρ | 1.0 | 1.2 | 1.5 | 2.0 | 2.7 | ≥4.0 |
|---|---|---|---|---|---|---|
| g(ρ) | 0.500 | 0.566 | 0.646 | 0.750 | 0.858 | 1.000 |

两点值得注意：

- **ρ < 1 ⟹ 规则未命中**（`docs/kb/KB4-attribution-model.md:327`）——
  没到阈值就是没到，g 不会给"差一点"发安慰分；
- **饱和点在 4**（同段），选 4 的理由写在
  `docs/kb/KB4-attribution-model.md:330`：**6 dB ≈ 4 倍尺度**。

**"6 dB ≈ 4 倍"是个漂亮的锚**：它把信号处理里熟悉的量级
（幅值 2 倍 = 6 dB……这里是 4 倍 ≈ 12 dB）落成了一个具体数字，
而不是拍脑袋定的。

布尔/枚举类证据走常数 `g_cat = 0.85`（`docs/kb/KB4-attribution-model.md:326`）——
它们没有"离阈值多远"，给一个固定的中高档。

### 6.2.2 `conf(f)`：这条特征本身有多可信

`conf(f)` 来自 C2 特征自身的置信度。几处关键封顶：

- `bandwidth.confidence` 上界 **0.6**，**实现不得提高**
  （`docs/kb/KB4-attribution-model.md:332-334`）；
- `coherence_torque_velocity` 在 `method == "fe_proxy"` 时 **×0.7**（同段）；
- `vel_fb.derived == true` 时频谱类整体 **×0.7**（同段）。

第三条呼应第 3 章 KB2 的一条实测（`docs/kb/KB2-waveform-formats.md:298`）：
`vel_fb` 由差分派生 ⟹ 频谱类判据置信度 × 0.7，**且不得放宽门限**。

**"派生"这件事不是中性的**：由差分得到的 `vel_fb` 当然能用，
但它的频谱可信度天然低一档，所以降权，**而不是提高门槛把它排除掉**——
排除会丢掉信息，降权只降低它的分量。

### 6.2.3 `n_factor(n/n_ref)`：样本量够不够

`n_factor = min(1, 0.6 + 0.4·log10(n/n_ref)/log10(4))`
（`docs/kb/KB4-attribution-model.md:352`）：

| n/n_ref | 0.5 | 1 | 2 | 4 |
|---|---|---|---|---|
| n_factor | 0.40 | 0.60 | 0.80 | 1.00 |

`n_ref` 是**逐判据登记**的样本量基准（`docs/kb/KB4-attribution-model.md:336-348`）：
Welch 段数 4、带内 bin 15、3 dB 带宽 bin 8、dwell 1、rest 1、move 4、
事件计数 3、path 1、加/减速各 50；其余下限在
`docs/kb/KB4-attribution-model.md:350`（ripple ≥ 2 整转、settling ≥ 3、
vision ≥ 20、匹配对 ≥ 3）。

**关键**：缺 `n` / `n_ref` **禁止**默认 `n_factor = 1`，
一律记 `MissingSampleScale` 进 `rules_skipped`
（`docs/kb/KB4-attribution-model.md:354`，A-102 ③）。

这条与第 3 章"null ≠ 0"同源：
**不知道样本量，不能假装样本量充足**。

### 6.2.4 `band_factor(f0)`：这个频点看得见吗

（`docs/kb/KB4-attribution-model.md:357-358`）：

| 情形 | band_factor |
|---|---|
| 非频域判据 | 1.00 |
| `f0 ≤ 0.5·f_b` | 1.00 |
| `0.5·f_b < f0 ≤ f_b` | **0.80** |
| `f0 > f_b` | 阻塞（`S` 不存在） |

`f_b` 是可靠频带（`f_b = f_N/1.25`，
`docs/kb/KB3-tuning-rules.md:2017`）。

**注意最后一行是"阻塞"而不是"降权"**：
频点超出可靠频带，这条证据**根本不存在**，
不是"存在但不可信"。这是第 3 章"看不见 ≠ 没有"的又一次现身。

## 6.3 聚合：从一条证据到一个置信度

四个因子给出单条强度，聚合分五步
（`docs/kb/KB4-attribution-model.md:363-369`）：

1. **k < 2 ⟹ INV-10 ⟹ 移到 `considered`，不计算 C**
   （`docs/kb/KB4-attribution-model.md:363`）——
   证据不足 2 条的假设**不参与排序**，它进的是"考虑过但没站住"；
2. `A_sup = 0.55·Smax + 0.45·Srest`（`docs/kb/KB4-attribution-model.md:363-369`）——
   最强的那条证据占 55%，其余合成 45%；
3. `A_con = min(0.5, Σ v_j)`（同段）——反证扣分，最多扣 0.5；
4. `C_mid = A_sup·(1 − A_con)`（同段）；
5. `C(h) = min(C_mid, 各 CAP ceiling)`（同段）。

**0.55 / 0.45 这个配比**意味着：一条特别强的证据（0.9）
加三条中等证据（各 0.5），
`A_sup = 0.55×0.9 + 0.45×0.5 = 0.495 + 0.225 = 0.72`——
**单条压过多条，但多条仍然有分量**（纯 0.55/0.45 的话三条会更高）。

最终还要乘一次**缺席扣减**：

```
overall_confidence = C(H_primary) × (1 − 0.05 × min(4, |distinct blocked_by|))
```

（`docs/kb/KB4-attribution-model.md:369`；C3 侧同一公式在
`docs/contracts/C3-diagnosis.md:1030-1037`。）

注意扣减按**去重后的缺席原因数**计，不是按登记行数——
十条规则因为同一个原因缺席，只扣一次。
这条设计防止"缺席"变成一种可以刷分的机制。

### 6.3.1 反证扣分与否决，是两件事

反证扣分档位（`docs/kb/KB4-attribution-model.md:476-477`）：

| 情形 | v_j |
|---|---|
| ρ′ ≥ 2 | 0.20 |
| 1 ≤ ρ′ < 2 | 0.10 |
| ρ′ < 1 | 0.05 |
| 依赖为 null | **0.00**（不算反证） |

最后一行很重要：**"因为数据缺失所以看起来不支持"不是反证**。
它已经在缺席扣减里被算过一次了，不该再扣一次——
否则"没数据"的样本会被双重惩罚。

而**否决 ≠ 扣分**（`docs/kb/KB4-attribution-model.md:480-483`）：
命中 KB3 排除项的否决条件 ⟹ **直接判该假设不成立**，
不入 `hypotheses`，改登 `considered`。

**"扣分"是"它可能对，但弱"；"否决"是"它不成立"**。
两者的处置完全不同：扣分后还留在报告里供人判断，
否决后连候选都不算。

## 6.4 CAP：封顶表

CAP 表共 **12 条**（`docs/kb/KB4-attribution-model.md:496-507`），
它给每类结论一个**置信度上限**。

| CAP | 上限 | 管什么 |
|---|---|---|
| CAP-1 | 0.60 | 通用上限 |
| CAP-2 | 0 / 共现 0.40 | 软件族：因果不可言，只许共现 |
| CAP-3 | 0.55 | — |
| CAP-4 | 0.65 | — |
| CAP-5 | 0 | 禁入 `hypotheses` |
| CAP-6 | 0.55 | — |
| CAP-7 | 频谱类 ×0.70 | 派生/代理特征 |
| CAP-8 | 0.40 | `alignment_residual_ms > τ_u` 或对齐窗 ≤ τ_u |
| CAP-9 | 0.60 | 反事实自检 UNRESOLVED |
| CAP-10 | 0.60 | 同族 not_evaluable ≥ 3 条 ⟹ 每条 −0.05（总扣 ≤ 20%） |
| CAP-11 | 0.60 | — |
| CAP-12 | 检出类可 `simulation_validated`、改进量恒 `rule_heuristic` | — |

三条使用纪律：

- **CAP 只读 C2 字段与 C4 记录，不看规则结论**
  （`docs/kb/KB4-attribution-model.md:509-512`）——
  避免"用结论给结论封顶"的自指。这条和第 2 章
  "落码侧与复算侧不得各自发明"是同一个思路。
- **多条截断同时触发 ⟹ 取最小上限（不连乘）**
  （`docs/kb/KB6-coupling-and-calibration.md:555-556`）——
  避免"截断越叠越狠"直到什么都说不出来。
- **截断只降不升；禁止实现成"LLM 觉得证据不足就降 0.1"**
  （`docs/kb/KB4-attribution-model.md:555-556`）。

## 6.5 排序：可判定的名次

KB4 §2.9 是排序口径（`docs/kb/KB4-attribution-model.md:571`），
而 C3 规则 20 把它变成**机器必判**的三连
（`docs/contracts/C3-diagnosis.md:1102-1137`）：

- `C3-R20-rank-contiguous`：rank 连续；
- `C3-R20-rank-monotonic`：rank 单调；
- `C3-R20-primary-is-rank1`：`primary` 必须等于 rank 1。

可判前缀是 `(severity↑, −C)`，并列时用 `fault_mode` 兜底
（`docs/contracts/C3-diagnosis.md:1102-1137`）。

**为什么先比 severity 再比 C？**
因为严重度是**后果**，置信度是**把握**。
一条"置信度只有 0.5 但一旦发生会撞机"的假设，
应该排在"置信度 0.9 但只是轻微抖动"的假设前面——
**先看后果，再看把握**。

并列落在 `fault_mode`，**不落 `rule_id`**（`docs/kb/KB4-attribution-model.md:611-615`）——
因为 `rule_id` 在假设级没有载体（一条假设可以由多条规则支撑）。

排序还有一条"队长锚定"：并列带与引擎共用 `confidence.rank_band_c`，
读产物里的**两位显示值**，±0.01 队长锚定
（`docs/wiki/04-validation-report-cli.md:23`）。

这条细节解决了一个真实问题：
引擎内部用全精度排序，报告里只印两位小数。
如果两条假设的 C 分别是 0.6543 和 0.6541，
报告上会印成 0.65 和 0.65——**看起来并列**。
队长锚定就是告诉读者"这两条在显示精度下算并列"，
免得读者以为排序是随机的。

## 6.6 算例：手算一遍

### 6.6.1 算例 A 的六个 n/n_ref

`resolution_hz = 1.95`（= 8000/4096）
（`docs/kb/KB4-attribution-model.md:389`），
三 dB 带宽 `three_db_width_bins = 22`（= `round(1181/27/1.95)`）（同段）。

六行 n/n_ref（`docs/kb/KB4-attribution-model.md:401`）：
Welch 8/4、带内 bin 96/15、3 dB 宽 22/8、dwell 3/1、rest 2/1、move 6/4。

**手算 n_factor**：

| 因子 | n/n_ref | log10 比例 | n_factor |
|---|---|---|---|
| Welch 段数 | 8/4 = 2 | 0.301 | 0.6+0.4×0.301/0.602 = **0.80** |
| 带内 bin | 96/15 = 6.4 | 0.806 | 0.6+0.4×0.806/0.602 = **1.00**（饱和） |
| 3 dB 宽 | 22/8 = 2.75 | 0.439 | 0.6+0.4×0.439/0.602 = **0.89** |
| dwell | 3/1 = 3 | 0.477 | **0.92** |
| rest | 2/1 = 2 | 0.301 | **0.80** |
| move | 6/4 = 1.5 | 0.176 | 0.6+0.4×0.176/0.602 = **0.72** |

（分母 `log10(4) = 0.602`。）这些值与 KB4 算例 A 逐格一致。

**手算 g(ρ)**：某条证据 ρ = 1.5 ⟹ `g = 0.5 + 0.5×log10(1.5)/log10(4)
= 0.5 + 0.5×0.176/0.602 = 0.5 + 0.146 = **0.646`**
——正是锚点表里的 0.646（`docs/kb/KB4-attribution-model.md:330`）。

### 6.6.2 算例 B：一条不到 0.6 的假设

算例 B 的逐格（`docs/kb/KB4-attribution-model.md:451-463`）：

```
Smax = 0.597
Srest = 1.254 / 3 = 0.418
A_sup = 0.516
A_con = 0.15
C_mid = 0.439
C = 0.44  < 0.60
```

**0.44 < 0.60 触发了 C3 规则 5**：
置信度 < 0.6 时 `next_data_to_collect` **不得为空**
（`docs/contracts/C3-diagnosis.md:967`）。

KB4 接着算了一步"补采之后"
（`docs/kb/KB4-attribution-model.md:465-467`）：
`A_sup ≈ 0.55`、`C ≈ 0.47`，**仍 < 0.6** ⟹
**单靠加样本救不回来，必须换激励**。

这是全章最实用的一段：
**"再多来点同样的数据"有时候没用**。
如果 C 提不上去，缺的不是数量，是**能区分假设的激励**。
一个连"再采 100 份"都救不回来的假设，
正确处置是告诉操作员"换个激励方式"，
而不是"再采 100 份"。

### 6.6.3 一条不许反推的数

`bins_in_band` 是显式登记量，**不得反推**
（`docs/kb/KB4-attribution-model.md:407-423`；C2 侧同
`docs/contracts/C2-features.md:407-423`）。

KB4 给了一个具体的反面例子
（`docs/kb/KB4-attribution-model.md:351`）：
用 `reliable_band_hz / resolution_hz` 反推得 ≈1641，
而算例 A 的登记值是 **96**——**差一个量级**。

为什么差这么多？因为"频带内有多少个 bin"取决于
**实际有多少样本落在频带里**（门控、剔除、段覆盖），
不是频带宽度除以分辨率。频带是**许可**，bin 数是**实况**。

## 6.7 反事实自检：归因之前必须跑

KB4 §4 是"反事实自检（归因前必跑）"（`docs/kb/KB4-attribution-model.md:838`）。

**机制**（`docs/kb/KB4-attribution-model.md:840`）：问"**如果这条假设不成立，我还应该看到什么**"，
然后**去找那个东西**。找到了 ⟹ 假设被证伪。

**三态**（`docs/kb/KB4-attribution-model.md:844-846`）：
PASS / FAIL / UNRESOLVED。UNRESOLVED ⟹ CAP-9 封顶 0.60，
并在 `not_evaluable` 追加"反事实项 `<id>` 不可求值"。

**held-out 约束**（`docs/kb/KB4-attribution-model.md:848-850`）：
检查项求值的 `kind`/通道必须与形成该假设的证据**不相交**。

这条是整节的技术核心。想象一条假设是
"跟随误差来自前馈失配"，它的证据是加速度与误差的相关性。
现在做反事实检查：如果是前馈失配，那么**稳态段**不该有这个相关性。
如果你用**同一段加速度数据**去检验它，
那是拿"假设的证据"检验"假设"——**必然通过**。

held-out 强制你换一条**不相关的数据面**去看。
§4.2 的检查项表共 **14 行**（`docs/kb/KB4-attribution-model.md:854-869`），
每行给"若 h 不成立还应看到 / 求值面(held-out) / FAIL 后果"。

## 6.8 ECE：置信度自己也要被校准

KB4 §2.6 是 ECE（`docs/kb/KB4-attribution-model.md:514`），
§2.8 讲 ECE 恶化时的回溯（`docs/kb/KB4-attribution-model.md:556`）。

C5 把 ECE ≤ 0.10 称作"**本项目最重要的单一指标**"
（`docs/contracts/C5-evaluation-protocol.md:78`）。

**为什么是它**：Top-1 命中率可以靠"只报最有把握的那一条"刷上去，
拒答正确率可以靠"什么都拒答"刷上去——
**但 ECE 同时惩罚这两个动作**。
一个把置信度一律报 0.9 的系统，
它的 ECE 一定很差，因为它的自信和它的正确率不匹配。

第 7 章会看到本仓当前的 ECE 实测值是 **null**——
**不是 0，是 null**。null 在这里的含义是"分母为零，不给数"
（`docs/wiki/07-run-guide.md:56`），和第 3 章"null ≠ 0"是同一条纪律。

## 6.9 动手：手算一条 S(e)

**第一步**，挑 KB4 算例 A 里的任意一条证据，
把它抄成四栏：`ρ`、`conf(f)`、`n/n_ref`、`f0`。

**第二步**，手算：

```
g(ρ)        = 0.5 + 0.5·min(1, log10(ρ)/log10(4))
n_factor    = min(1, 0.6 + 0.4·log10(n/n_ref)/log10(4))
band_factor = 查表（非频域 1.00 / ≤0.5f_b 1.00 / ≤f_b 0.80 / >f_b 阻塞）
S(e)        = g(ρ) × conf(f) × n_factor × band_factor
```

**第三步**，和 KB4 算例 A 的对应格子比
（`docs/kb/KB4-attribution-model.md:379-467`）。
差一位？**不要四舍五入掩盖**——
KB0 §6 检查 26 附近写着"两处数值不一致时**禁止**用'取整口径差异'糊过去"
（`docs/kb/KB0-conventions.md:169-171`）。

**第四步**：把 `f0` 改到 `f_b` 之上，看 `band_factor` 怎么变，
以及 `S(e)` 变成什么（不是变小，是**不存在**）。

**动手验收**：你能对着 `docs/kb/KB4-attribution-model.md:451-463`
把 `C = 0.44` 复算出来，并说出它触发了哪条契约。

## 习题

1. `g(ρ)` 的饱和点取 4，理由是"6 dB ≈ 4 倍尺度"
   （`docs/kb/KB4-attribution-model.md:330`）。
   如果取 2，模型会有什么系统性偏差？
2. `A_sup = 0.55·Smax + 0.45·Srest`（`docs/kb/KB4-attribution-model.md:363-369`）：
   两条证据 (0.9, 0.5) 与三条证据 (0.5, 0.5, 0.5)，
   谁的 `A_sup` 高？**这说明什么**？
3. 反证里"依赖为 null ⟹ v_j = 0.00"
   （`docs/kb/KB4-attribution-model.md:476-477`），
   而缺席又要按 `blocked_by` 扣减（`docs/kb/KB4-attribution-model.md:369`）。
   如果 null 也给 0.20，会双重惩罚什么？
4. CAP 只读 C2 与 C4，**不看规则结论**
   （`docs/kb/KB4-attribution-model.md:509-512`）。
   如果 CAP 允许读规则结论，会出现什么自指？
5. 反事实自检的 held-out 约束（`docs/kb/KB4-attribution-model.md:848-850`）：
   举一个"不 held-out 就必然通过"的检查设计。
6. 算例 B 里补采之后 C 仍 < 0.6
   （`docs/kb/KB4-attribution-model.md:465-467`）。
   `next_data_to_collect` 里应该写"多采同样的数据"还是"换激励"？
   依据是哪一条契约？
