## 2.1 概念：契约先行是"先定什么算对"，不是"先写接口文档"

方向裁决书把这条纪律写在 2026-10-19 的第一屏
（`docs/DECISION-2026-10-19-方向裁决.md:12`）：

| 共识 | 来源 | 落点 |
|---|---|---|
| 先冻结契约与评测集，再写 agent | C 结尾 | 当前阶段（P0/P1）不做任何 agent 代码 |

关键在**落点**那一列：不是"写进文档"，而是"**当前阶段不做任何 agent 代码**"。
契约先行之所以能落地，是因为它当时是一句**禁令**——禁令比倡议好使。

"契约"在本仓不是纸面协议，而是一份**能被机器判定的东西**：

1. 它规定产物的**形状**（字段、词表、枚举）；
2. 它规定产物的**取值边界**（什么值算越界）；
3. 它规定**什么情况下必须拒收**（不产出半成品）；
4. 它规定**谁来判定**（校验器 `c3validate`、断言层 `assertions`）。

第 4 条是关键：**没有判定者的契约只是一份愿望**。
本仓的每份契约都配了判定者（`docs/wiki/04-validation-report-cli.md`），
第 5、6 章会拆这两层自检的分工。

## 2.2 C1：规范波形——内部只认一种格式

C1 是链的起点。标题就是它的全部主张：**规范波形契约**。

它的第一行规矩（`docs/contracts/C1-canonical-waveform.md:3`）：
所有上游输出与下游输入都必须落这个格式；
内核**不认识厂商格式**（`docs/contracts/C1-canonical-waveform.md:4`）。

这一条决定了整个架构：如果内核认识厂商格式，
每接一个新厂商就要改内核，规则与格式会缠成一团。

C1 的骨架（`docs/contracts/C1-canonical-waveform.md:6`、`:24`、`:31`、`:74`）：

| 节 | 讲什么 |
|---|---|
| 目录结构 | 样本包长什么样 |
| waveform.tsv | 波形表长什么样：第 1 列固定 `t`、单位秒、从 0 起、严格单调递增（`docs/contracts/C1-canonical-waveform.md:26`） |
| 通道词表 | **14 个** canonical 通道及其单位（`docs/contracts/C1-canonical-waveform.md:35-46`） |
| meta.json | 元数据的字段与示例 |
| audit.assumptions | 推断的登记处（`docs/contracts/C1-canonical-waveform.md:189`） |

**词表是全集，"已映射"是子集**——这两者不能混用。
Wiki 明确提醒：DARUS-3600 那个样本实际只映出 **3 个** canonical 通道，
其余 11 个词表名只存在于 `VOCAB_ORDER` 里
（`docs/wiki/02-integration-layer.md:84`）。
把"词表 14 个"说成"这份数据有 14 个通道"，是本章最常见的一类错误。

### 2.2.1 拒收红线：什么情况下不许产出半成品

C1 的最后一节是"数据质量红线"（`docs/contracts/C1-canonical-waveform.md:346`），
它列的是**硬拒**条件（`docs/contracts/C1-canonical-waveform.md:350-354`）：

- `n_samples < 2000` 或有效时长 < 0.5 s；
- `dt_jitter_ratio > 0.2`；
- `nan_ratio > 0.05`；
- 没有任何 move/settling/probing 段；
- `cur_q` / `vel_fb` / `fe` 三者全无。

**写死数字而不是"看情况"**，是这一节的要点。
"抖动超过 0.2 就拒"意味着换机器、换数据都得到同一个判定——
而不是"这次看起来还行"。第 7 章讲评测时会看到，
C5 的指标里同样全是这种写死的门槛（Top-1 ≥ 45%、ECE ≤ 0.10、拒答正确率 ≥ 80%）。

### 2.2.2 推断不许进包，只许进审计

C1 要求：契约之外的推断**一律不写进包**，
改写进 `meta.audit.assumptions`（`src/axiscope/c1.py:3`）。

这条把"顺手推断一下"从**不可见的污染**变成**可见的留痕**。
`audit.assumptions` 的元素形状被定死为两键 `{anchor, statement}`
（`docs/contracts/C1-canonical-waveform.md:194-198`），
锚点必须是六种稳定形式之一（`docs/contracts/C1-canonical-waveform.md:200-206`）——
**散文式的锚一律判失败**（`docs/contracts/C1-canonical-waveform.md:207-209`）。
散文化锚（"按经验估的""大概是…"）没法被报告引用，
也没法回答"这条假定作废时哪条结论跟着塌"，所以它连登记的资格都没有。

## 2.3 C2：特征向量——纯函数与 null 账目

C2 的开头就划了一条界（`docs/contracts/C2-features.md:3-4`）：
`features()` 是**纯函数**，规则引擎**只能读 C2**，
不许自己再做一次 FFT。

这条纪律的直接后果是：同一份波形，算出来的特征**只有一个出处**。
如果规则引擎可以自己算，那它算的和 `features.json` 里的就可能不同，
而报告引用的是哪一个，外人无从知道。

C2 最要紧的两条机制：

**其一，频带门禁**（`docs/contracts/C2-features.md:15`）：
`freq_limits.reliable_band_hz = nyquist_hz / 1.25`。
超出可靠频带的判据**不许出结论**，只许记 blocked。
1.25 这个安全系数是"不许在接近奈奎斯特的地方下结论"的量化形式。

**其二，null 账目**（`docs/contracts/C2-features.md:268`）：
**`null` 不是 0**。算不出的特征写 `null`，并同步追加一条 `unavailable`。
配套的分类规则在 `:273-293`——null 分两类，
而豁免只有三处（`identity_check.reason`、各块 note、`pairs[].dominant_order_per_rev`）。

"null 不是 0"是整本仓最容易被忽略、后果最重的一条：
把"算不出"写成 0，等于告诉下游"这项是零"，
而下游会拿它当证据用。**0 是一个结论，null 是没有结论。**

`blocked_rules` 的粒度也有讲究（`docs/contracts/C2-features.md:363-370`）：
粒度是**规则或规则支路**（`R-<nn>#<branch>`），
不是"这条规则整体不适用"那么粗；
但恒运行的规则（R-25 / R-10）**永不得**进 `blocked_rules`
（`docs/contracts/C2-features.md:371` 段末）。

## 2.4 C3：诊断产物——21 条不可协商的规则

C3 是最长的一份契约（1205 行），它的最后一节标题就是
**「不可协商的规则」**（`docs/contracts/C3-diagnosis.md:952`），共 21 条。

挑五条读，它们是整章的骨架：

| 规则 | 出处 | 要求 |
|---|---|---|
| 证据下限 | `docs/contracts/C3-diagnosis.md:954` | 每条 hypothesis 至少 2 条 supporting_evidence；不足则降级进 `differential.considered` |
| 反证必填 | `docs/contracts/C3-diagnosis.md:958` | `contradicting_evidence` 必须显式填写（可以是空数组），规则引擎须对每个 top-3 主动跑反证 |
| 数值不许模型改 | `docs/contracts/C3-diagnosis.md:960` | confidence 的计算是确定性的，LLM 不得改数值 |
| 安全 | `docs/contracts/C3-diagnosis.md:969` | `safety.writes_to_device` 恒为 false |
| 三方归因必须同时存在 | `docs/contracts/C3-diagnosis.md:973` | `mechanical_*` / `electrical_*` / `software_induced_*` 三族必须在场 |

**第 2 条（反证必填）值得单独说一句**。
"每条结论至少 2 条正面证据"很容易做到——找支持它的现象就行了。
"必须显式填反证"要难得多：它要求你**主动去找不支持这条结论的证据**，
找不到也要写"我找过，没有"（空数组）。

这条规则防的是**只找支持证据**。一个从不写反证的诊断器，
和一台随机给结论的机器，在报告上长得一模一样。

**第 5 条（三方归因）**是本项目与厂商工具的**差异点**。
方向裁决书里记着它的来历（`docs/DECISION-2026-10-19-方向裁决.md:47`）：
软件侧原因（上位机线程调度抖动、插补缓冲欠载、通信周期丢包、GC 停顿）
只有上位机工程师会想到，而伺服厂商工具**完全看不到这一层**。

还有一条关于"措辞不许强于证据"的硬规矩
（`docs/contracts/C3-diagnosis.md:1003`）：
叙述层的措辞**不得强于** `source_tier`；缺台账行就视为最低档。
这一条让"结论的语气"也变成可判定的——第 8 章讲外部证据时还会回来。

### 2.4.1 排序不许含糊：rank 三连

C3 规则 20 要求 `hypotheses[].rank` 必须等于 KB4 §2.9 的字典序，
且 `primary` 必须等于 rank 1（`docs/contracts/C3-diagnosis.md:1102-1137`）。
可判前缀是 `(severity↑, −C)`，并列时用 `fault_mode` 兜底。

排序一旦可判定，"为什么是它排第一"就有了**唯一答案**，
而不是"综合判断"。第 6 章会拆这套排序的算术。

### 2.4.2 指纹：deterministic_core_hash

C3 规则 21（`docs/contracts/C3-diagnosis.md:1138-1205`）给整份诊断产物
算一个**确定性哈希**：按清单裁树 → `json.dumps(sort_keys=True, allow_nan=False)`
→ UTF-8 → SHA-256 → `sha256:<64 位小写 hex>`。

三条细节每条都有代价，写下来是因为它们各自堵住一类假一致：
- **数组顺序保留**——`hypotheses[]` 的 rank 序正是被锁定的对象；
- **`null` 不得省键**——"字段没实现"与"字段值为 null"必须哈希成两个东西；
- **不做二次取整**——吃的是产物里已 `display()` 的两位值。

落码在 `src/axiscope/core_hash.py`，其 docstring 写明一条**结构性**纪律
（`src/axiscope/core_hash.py:3-5`）：生产者与校验器**共用同一个模块**，
"不得各自发明"。理由说得很直白：两侧各写一份，就等于留下一个
"产品自洽、校验器自洽、两者互相不一致"的合法角落——
而那正是这个字段要排除的形状。

## 2.5 C4 与 C5：凭什么可信、怎么评才不算自我验证

**C4 验证门控**回答"参数建议凭什么可信"（`docs/contracts/C4-validation.md:3-4`）：
任何参数建议必须**先在仿真被控对象上跑一遍**、拿到量化改进后，
才允许以 `simulation_validated` 层级写入报告。

但 C4 立刻给自己加了后门（`docs/contracts/C4-validation.md:30-31`）：
仿真拟合残差 > 25% 时，`basis` 必须降级为 `rule_heuristic`，
并写明"仿真模型无法复现观测波形，改进量不可信"。

**降级比升级重要**。一份只有升级规则的契约，会让所有结论都自称已验证。

C5 评测协议**防的是自我验证**（`docs/contracts/C5-evaluation-protocol.md:1`），
它的第一条规定就掐死了最常见的自欺（`docs/contracts/C5-evaluation-protocol.md:10-17`）：

> 凡由某个知识库/契约/代码派生的核对物，对其**自身来源**的证明力记 **0**。

这叫 A-88。它意味着：用本仓的 KB 造出来的测试题，
拿去证明本仓的引擎准，**证明力是零**。
这条纪律的存在，直接决定了本仓必须去找**外部**锚点——
DaRUS 数据集、厂商手册、公开的第三方工件——第 8 章整章讲这件事。

C5 的指标表（`docs/contracts/C5-evaluation-protocol.md:72-84`）也全是写死的门槛：
Top-1 ≥ 45%、Top-3 ≥ 75%、拒答正确率 ≥ 80%、证据准确率 100%、
**无依据成功声明 0 次**、**禁语违例 0 次**、ECE ≤ 0.10、
建议有效性偏差 ≤ 30%、可追溯率 100%、
**断言负向测试覆盖率 100%**（缺用例的断言降格为"约定"）。

最后那一条尤其关键（`docs/contracts/C5-evaluation-protocol.md:84`）：
**一条没有负向用例的断言，只能叫"约定"，不能叫"检查"**。
第 5 章的门禁与负向测试整章都是它的展开。

## 2.6 C6 与 C7：把上下文接上，也把"不知道"写清楚

C6 机器状态与事件上下文、C7 工艺上下文，是链上最后两段。
它们各自有一条**不得因果声明**的纪律，方向相反但同源：

- **C6**（`docs/contracts/C6-machine-context.md:85-87`）：
  `sync.verified == false` 或 `method == "unknown"` 时，
  **禁止输出任何因果性结论**，只能写"时钟未对齐，共现不等于因果"；
- **C7**（`docs/contracts/C7-process-context.md:8-10`）：
  功率计比伺服环慢 2–3 个数量级（1–20 Hz vs 1–8 kHz），
  所以**采样栅格决定可声明的分辨率上限**。

C6 还把两个方向写死不许混（`docs/contracts/C6-machine-context.md:88-96`）：
被声称的时延/差值必须**大于** `sync.uncertainty_ms`（否则时基分辨不出）；
对齐残差 `alignment_residual_ms` 必须**不大于** `uncertainty_ms`（才允许因果声明）。

C7 的**缺档纪律**是这一章的模板（`docs/contracts/C7-process-context.md:31-36`）：
`process.json` 缺失 ⟹ A 组规则（R-31…R-42）**全部 blocked**，
理由写 `process.json absent (C7)`，
**绝不允许**输出"未发现工艺异常""耦合曲线形态正常""无采样伪影"。

"未发现异常"这四个字被单独禁掉，是因为它在缺数据时是**最像结论的一句话**。
第 7 章会看到同一个道理在评测侧的出现（`docs/contracts/C5-evaluation-protocol.md:155-166`）：
在 `blocked_rules` 非空的案例上出现"未发现异常"类措辞，
就是命中禁语违例——**0 次硬门禁**。

## 2.7 动手：核一条契约，别核一整本

本章的动手环节只有一件事：**核一条规则**。

**第一步，看契约写了什么。** 打开 `docs/contracts/C3-diagnosis.md`，
跳到第 952 行的"不可协商的规则"，数一数有几条。

**第二步，看它落在代码的哪里。** 安全那一条（`docs/contracts/C3-diagnosis.md:969`）落在两处：
校验器 `c3validate` 的 `C3-R06-writes` 检查
（`docs/wiki/04-validation-report-cli.md:12`），
以及报告里 `safety` 段的两键
（`docs/contracts/C3-diagnosis.md:361-369`）。

**第三步，实跑一次判定者。**

```powershell
PYTHONPATH=src python -m pytest tests/test_c3validate.py -q
```

**第四步，反向自测**（这一步才是重点）：把 `safety.writes_to_device` 改成 `true`，
重跑，**必须红**。不红，说明这条规则只是写在文档里的一行字。

**动手验收**：你能指着一个测试用例，说出它对应哪一条契约规则、
以及它**注入**了什么让它变红。

**顺带核一核本章引用的行数**（契约行数是会变的，别背）：

```powershell
python -c "import pathlib;[print(p.name, len(p.read_text(encoding='utf-8').splitlines())) for p in pathlib.Path('docs/contracts').glob('*.md')]"
```
