## 3.1 概念：知识库不是文档，是"可被机器引用的判据"

本仓的 docs 比代码重——**27 份 md 对 15 个 py**
（`docs/wiki/06-docs-system.md:3`）。这在工业项目里通常被当成缺陷，
但这里它是**设计**：文档是规范本体，生产代码是它的一部分实现。

Wiki 把这句话写得很直白（`docs/wiki/06-docs-system.md:3`）：
文档是被测试和探针引用的**规范本体**。

于是"写进知识库"这件事有了硬门槛。KB3 开头就是一条禁令
（`docs/kb/KB3-tuning-rules.md:4`）：

> 规则引擎**不允许自带 FFT、不允许自带未经本文件登记的字面量阈值**。

这条禁令一立，知识库的性质就定了：它不是"参考资料"，
它是**阈值的唯一出处**。规则引擎不许自己发明数字，
所以每一条数字都必须能在知识库里找到出处——
而"找到出处"这件事，是可以机器检查的（§3.6）。

## 3.2 命名空间：两套扁平编号

知识库里有两套编号，各管一维。

**其一，规则编号 `R-NN`**（`docs/kb/KB0-conventions.md:7`）——
扁平命名空间，不按文件分段。原因写在 KB0 里
（`docs/kb/KB0-conventions.md:18`）：`R-01…R-30` 由 KB3 分配，
`R-31+` 保留给 KB6。

**其二，裁决编号 `A-NN`**（`docs/kb/KB0-conventions.md:189`）：
唯一且连续，取最大号 +1，不得跳号、不得复用。
当前连续到 **A-133**（`docs/kb/KB0-conventions.md:549`）。

为什么裁决也要编号？**因为裁决是资产**。一条"我们决定了什么"的记录，
如果只有一个散落的段落，三个月后没人知道它改了什么、为什么改。
给它编号，它就成了**可被引用、可被回溯、可被撤销**的东西。

裁决还有一条铁律（`docs/kb/KB0-conventions.md:5`）：
**新增条目只能追加，不得改写已引用的编号语义**。
编号一旦被引用，它的含义就冻结了——想改语义就发新编号。

## 3.3 三大族与 22 个 slug：归因的名字空间

KB0 §2 写死了归因三大族（`docs/kb/KB0-conventions.md:20`），
共 **22 个 slug**：机械 8 / 电气 7 / 软件诱导 7
（`docs/kb/KB0-conventions.md:24-33`）。

KB4 的归因树叶子集合**必须等于**这 22 个
（`docs/kb/KB4-attribution-model.md:3-4`、`:143`）——
不是"大约 22 个"，是**集合相等**，否则引用完整性检查判失败。

这 22 个 slug 是**受控词表**，不是描述性标签。C3 规则 14 明确规定
（`docs/contracts/C3-diagnosis.md:986-987`）：
`fault_mode` 必须取 KB0 §2 的全量 slug，**禁止**用显示名。

"禁止用显示名"这一条有实际后果：显示名会变（要本地化、要改措辞），
而 slug 不变。一份报告里如果写的是显示名，
三年后没人能确定它当时说的是哪个具体故障。
所以 slug 是**接口**，显示名是**渲染**。

**族级登记的键名还有一条纪律**（`docs/kb/KB4-attribution-model.md:300-306`）：
族级登记项的 JSON 键是 `family`（**不是** `fault_mode`）。
`software_induced_error` 出现在 `hypotheses[].fault_mode` 里就是结构违规，
报告不得下发。

## 3.4 五档 tier：证据出处的分级

KB0 §4 规定证据出处 tier（`docs/kb/KB0-conventions.md:56`），
权威字段名是 **`source_tier`**（A-54）——历史名 `evidence_tier` 就地改名，
不再新增（`docs/kb/KB0-conventions.md:58`）。

值域**恰好五个**（`docs/kb/KB0-conventions.md:58`、`:70`；KB8 亦重申
`docs/kb/KB8-benchmark-cases.md:52`）：

| 档 | 是什么 |
|---|---|
| `T1-a` | 公开真实测量数据集（DaRUS，CC BY 4.0） |
| `T1-b` | 外部公开故障数据集（只计二分类，禁映射 slug） |
| `T1-c` | 自采真实测量（非产线） |
| `T2` | 文献 |
| `T3` | 本项目自造的仿真集 |

这套 tier 的用处不是"给证据排座次"，而是**给措辞封顶**。
KB4 §2.10 规定（`docs/kb/KB4-attribution-model.md:660-665`）：
每条结论在 `audit.tier_ledger[]` 里带 `source_tier`；
**缺行就按 T3 处理**；`T3` 的合法措辞上限是"管线上跑通/该形态可被检出"，
`T2` 的上限是"按〈出处〉的阈值"，**永不**写"手册原文确认"。

KB4 的 INV-13 更狠（`docs/kb/KB4-attribution-model.md:35`）：
出现「已核对/已验证/现场确认/手册原文确认/实测通过」而 `source_tier < T1` 时，
**拒绝出报告**——不是加个 disclaimer 降级，是**不出报告**。

## 3.5 最硬的一条：看不见 ≠ 没有

这一节是整章的重点，也是本仓被外部反复追问的那句话。

KB3 §0 的全局纪律第 2 条写死了它
（`docs/kb/KB3-tuning-rules.md:26-29`）：

> **绝对禁止把"看不见"写成"没有"。**

同一条纪律在契约侧还有两处更短的表述：
C2 写"**不得**输出'未发现共振'——那是把'看不见'说成'没有'"
（`docs/contracts/C2-features.md:353`），
KB4 的不变式 INV-11 写"不可观测只允许表述为 `not_evaluable` 条目"
（`docs/kb/KB4-attribution-model.md:33`）。

它落到具体数字上是这样一条链：

1. T1-a（DaRUS）样本的 `SampleTime` 恒 1 ms ⟹ fs = 1000 Hz
   （`docs/kb/KB7-dataset-da-rus-cat.md:204`）；
2. nyquist = 500 Hz，**可靠频带** `reliable_band_hz = nyquist / 1.25 = 400 Hz`
   （`docs/kb/KB2-waveform-formats.md:147`、`:156`）；
3. 而 R-03（kHz 级机械谐振检出）与 R-04（谐振-反谐振配对判定）
   要求的最低可靠频带是 **2000 Hz**
   （`docs/kb/KB0-conventions.md:14-15`；`docs/kb/KB3-tuning-rules.md:559-582`）；
4. 400 Hz < 2000 Hz ⟹ 这两条规则**必须**进 `blocked_rules`，
   报告侧**只能**写 `not_evaluable`。

KB2 把这条写成了**可执行的断言**
（`docs/kb/KB2-waveform-formats.md:161-164`）：

```
assert set(["R-03","R-04"]) ⊆ set(features.freq_limits.blocked_rules)
assert report.rules["R-03"].status == "not_evaluable"   # 出现 clear/no_resonance 即缺陷
```

**"出现 clear/no_resonance 即缺陷"**——这句话的分量比前面都重。
它不是"最好别这么写"，而是"这么写就是缺陷"。

为什么这么严？因为"未发现共振"这四个字在报告里**长得最像结论**。
读者（尤其是现场的工程师）看到它，第一反应是"检查过了，没有问题"——
而实际上只是"没看见"。这两句话之间隔着的，是一台 1 kHz 采样率的示波器。

同一条纪律在别处还有几处呼应：
- KB4 的 INV-11（`docs/kb/KB4-attribution-model.md:33`）：不可观测只允许表述为 `not_evaluable`；
- C7 缺档纪律（`docs/contracts/C7-process-context.md:31-36`）：
  数据不在 ⟹ 禁输出"未发现工艺异常""耦合曲线形态正常"；
- C5 的禁语违例（`docs/contracts/C5-evaluation-protocol.md:155-166`）：
  在 `blocked_rules` 非空的案例上出现"未发现异常"类措辞 ⟹ 命中违例，**0 次硬门禁**。

## 3.6 引用完整性：知识库自己的门禁

KB0 §6 是"引用完整性检查"（`docs/kb/KB0-conventions.md:137`），
共 **28 条**（`docs/kb/KB0-conventions.md:140-147`，末条见 `:305`）。

第 1 段就点明分工（`docs/kb/KB0-conventions.md:137`）：
**主线程负责，跨文件一致性不外包。**

28 条里最该被记住的是三条：

**检查 22**（`docs/kb/KB0-conventions.md:229`）：
任何"我们能自曝 X 类缺陷"的检查**必须附负向测试**，否则按约定处理。
C5 那边把它写成硬指标（`docs/contracts/C5-evaluation-protocol.md:84`）：
**断言负向测试覆盖率 100%**，缺用例的断言降格为"约定"。

**检查 23**（`docs/kb/KB0-conventions.md:234`）：
裁决新增的字段名必须有契约载体，且示例 JSON 里要出现一次。
一条只存在于裁决台账里的字段，等于**不存在的字段**。

**检查 27**（`docs/kb/KB0-conventions.md:304`）：
文档里凡"全量实测 / 行级差异数 / 恒等式成立或证伪"类断言，
须指向本仓一个**可重跑产物**并能复现该数字。

检查 27 是本章与第 9 章的接口：第 9 章要拿"账面 vs 实测"做对照，
而"账面"里那些数字**当年就要求挂着可重跑产物**——
所以今天才可能当场把它们核一遍。
