## 8.1 概念：数据分三种，只有一种能进仓

工业项目处理的数据大致分三类：

| 类 | 例子 | 能不能进仓 |
|---|---|---|
| **原始数据** | DaRUS 官网的 zip、厂商 CSV | **不能**——太大、许可不覆盖再分发 |
| **派生件** | 解出来的 TSV、特征 JSON、报告 | 能，但**必须**能追溯到原始件 |
| **存证** | 手册 PDF、厂商回函、抽取脚本 | 能——它们是"证明"本身 |

本仓的纪律是：**原始数据不入库，DOI 可重下**，
所以"可复算"的依据是**DOI + 抽取脚本**，而不是"数据就在仓里"。

这个取舍必须说清楚：**它把可复算的成本从"下载"转到了"重下"**。
读者要复算第 8 章的任何一条结论，得先按 DOI 把数据集拉下来
（约 596 MB，`docs/wiki/06-docs-system.md:49`），再跑仓内的抽取脚本。

**这不是缺陷，是许可与体积的必然结果**——但它也意味着
"可复算"这句话有前提：**原始件可得**。

### 8.2.1 ScienceDB：署名不能合并

README §2（`README.md:36`）：
**ScienceDB（中国科学院合肥物质科学研究院 等离子体物理研究所）——
CC BY 4.0，须独立署名**。

"独立署名"这四个字是重点。它意味着**不能把 ScienceDB 的署名
并进 DaRUS 那一行**——两者是不同作者、不同机构、不同许可主体。

README §3 同样点明这一点
（`README.md:55`）：**Zenodo 两包 —— CC BY 4.0，署名不得并入 DaRUS 一行**。

**为什么这条值得单独立一节**：
在 README 里把三组数据的署名写进同一段话，是最省事、也最省事的做法——
但那样读者引用时很容易只引第一组。
把"不得并入"写成硬规则，是把**合规成本前置到写作时**，
而不是留给读者在引用时踩坑。

## 8.3 侧车：19 个字段的来历证明

原始数据不入库，那"这个文件是哪来的"怎么记？**侧车**。

侧车的字段闭集是 **19 项**
（`docs/wiki/06-docs-system.md:45`）：
`url` / `retrieved_at` / `retrieved_by` / `publisher` / `license` /
`dataset_doi` / `original_filename` / `format_family` / `device_or_software` /
`sampling_rate` / `rows` / `channels` / `variable_semantics` / `derived_from` /
`upstream_id` / `md5` / `verified_against` / `verified_by` / `notes`。
全仓实测 **117 份**（同句）。

侧车读入的键闭集在代码里也是显式的
（`docs/wiki/02-integration-layer.md:26-30`）：
`publisher, license, dataset_doi, original_filename, url, sampling_rate`。

模板在 `data/PROVENANCE-TEMPLATE.md`（`docs/wiki/06-docs-system.md:45`）。

**这 19 个字段里最关键的是 `verified_by`**。KB7 把它叫"核对主体分级
（`verified_by` 不可转借）"（`docs/kb/KB7-dataset-da-rus-cat.md:384`）。

KB7 的登记纪律是
（`docs/kb/KB7-dataset-da-rus-cat.md:235-240`）：

> 本表每行数字都是主线程在本地实体文件上亲自跑出来的；
> **子智能体/第三方会话的报告对我们只是 `public-doc`，
> `verified_by ≠ self` 的数字不计入本表**。

**"不可转借"** 三个字道出了它的用法：
"我让某个子任务去核的"和"我自己打开文件核的"，
在证据等级上是**两回事**。

这条和第 4 章的 `external_reference` 是同一套逻辑，
只是落到了**文件字段**上。

## 8.4 四条硬规则：为什么"URL 打不开"不等于"不存在"

`docs/wiki/06-docs-system.md:46` 列了四条硬规则：

1. **派生件哈希只是自证**；
2. **文件名不是标识**（须 `upstream_id` + `md5` + `directoryLabel` 三件套）；
3. **URL 打不开不等于不存在**；
4. **核对判据要匹配文件形态**。

第 1 条要展开：派生件的 sha256 只能证明"**这个文件和那个文件一样**"，
不能证明"**这个文件来自那个来源**"。
哈希是**同一性**的证明，不是**来源**的证明。

第 3 条是实践中最常见的错误：
某个 DOI 打不开了，于是数据"不存在"？
正确的判断是"**现在打不开**"——
可能是对方站点改版、临时故障、或需要机构权限。
把"打不开"写成"不存在"，会让一份诚实的报告变成一份有事实错误的报告。

第 2 条是实测出来的：同一份 DaRUS 数据，
不同目录下的文件名可能相同也可能不同，
**只有 `upstream_id` + `md5` + `directoryLabel` 三件套**能定位它。

## 8.5 脱敏：只清三样，绝不碰署名

脱敏的规则在 KB2 §六（`docs/kb/KB2-waveform-formats.md:780`），
最关键的一句在 `:804`：

> 脱敏只清除主机路径 / ADS NetID / 绝对墙钟时刻，
> **绝不清除署名与 DOI，也不改动数值**。

**"也不改动数值"** 五个字是数据脱敏里最常被违反的一条。
脱敏时手一抖，把某个通道的数值改掉一点点，
整份数据就废了——而你**看不出来**。

字段级的具体规则（`docs/kb/KB2-waveform-formats.md:788-795`）：

| 原字段 | 替换为 |
|---|---|
| `File`（主机路径） | `[REDACTED_HOST_PATH]` |
| 导出/修改时间（绝对墙钟） | `[REDACTED_WALLCLOCK]` |
| `NetID`（ADS NetID） | `[REDACTED_ADS_NETID]` |
| `Port` 851 | 保留，或 `[PORT]` |
| `SymbolName` | **保留** |

注意 `SymbolName` 保留——它是**信号语义**，不是身份信息。

而署名必须保留（`docs/kb/KB2-waveform-formats.md:801-803`）：
Reichenbach, Thomas — University of Stuttgart（ROR 04vnq7t77）；
DOI `10.18419/DARUS-3600` 与 `10.18419/DARUS-5171`；许可 **CC BY 4.0**。

**脱敏与署名是直接冲突的两条要求**：
脱敏要抹掉"这台机器是谁的"，署名要写清"这份数据是谁的"。
前者是**隐私**，后者是**许可**。两者碰在一起时，
本仓的选择是**抹机器、留人**——
因为机器路径是内部信息，而署名是**法定义务**。

### 8.5.1 发布门：三 token 归零

脱敏不是"检查一下"，是**发布门**。门 token 三个
（`docs/kb/KB2-waveform-formats.md:816`）：

```
assertions.REDACT_TOKENS = ("Versuchsstand", "141.58.", "C:\\")
```

落码在 `src/axiscope/assertions.py:18`，命中计数在 `:130`：
`hits = [tok for tok in REDACT_TOKENS if tok in blob]`。

**三个 token 的选择很讲究**：
`Versuchsstand` 是德语"试验台"、是主机名的一部分；
`141.58.` 是内网 IP 段；`C:\\` 是 Windows 盘符路径。
它们覆盖了"主机路径 / ADS NetID / 绝对墙钟"这三类。

而 README §6 记着它的执行结果
（`README.md:74`、`:81`）：**已执行 2026-10-22**，
两个侧车登记 md5 前后对照
（Export10 `8cba13df…`→`178a6308…`、DD_head `995d0d91…`→`3f80439d…`）。

**md5 前后对照**这一条值得学：
改了文件就得记下改前改后的哈希。
这样以后任何人问"这个文件被动过吗"，有据可查。

KB2 里的实测计数（`docs/kb/KB2-waveform-formats.md:527-530`）：
`Versuchsstand` 1、`NetID` 32、内网地址（`141.58.` 网段）32、`C:`+反斜杠 1；
两个 `.source.txt` 侧车各再带 1 次 ⟹ `data/raw` 合计 `Versuchsstand` 4、盘符路径 3。

引擎产物侧（`docs/kb/KB2-waveform-formats.md:532`）：
`build/Export10_244531/` 实测 `Versuchsstand` **0**、IP **0**、盘符路径 **0**；
`NetID` 命中 **4**（**全是叙述文字**）。

最后这个括号里的说明是**脱敏的边界**：
`NetID` 这四个字符在报告正文里作为**叙述**出现（比如
"该数据来自 ADS NetID X 的设备"），不是**净 ID 本身**。
所以三 token 门判它无害。

**但这也暴露了一个真实的局限**：
token 门是**字面匹配**，它抓不到"用别的写法写的同一个主机名"。
第 10 章（若续卷）会说怎么补这一层。

### 8.5.2 三档值，四道门：一个比"漏了一处"更大的问题

写这一节的时候，本卷把 `data/probe_pii.py` 的扫描范围**往外挪了一格**。
原先它只扫 `data/raw/` 与 `build/`——也就是**只管数据**。
挪到"仓内跟踪文件"之后，它立刻报出四类东西：

| 档 | 形态 | 本卷动它之前的分布 |
|---|---|---|
| 主机路径 | `C:\…`（本机主机根目录；原值已按 §六 令牌化） | 数据侧清了；**文档侧半清**（同一批文档里路径清了、墙钟没清）；**脱敏脚本的规则里是原值** |
| 绝对墙钟 | ticks + 德语日期时刻 | 数据侧清了；**文档侧一处没清**（锚点状态下 `docs/kb/KB2-waveform-formats.md:52-53`、`docs/kb/KB7-dataset-da-rus-cat.md:183`、`data/research_5171_cdd.md:296-297`） |
| ADS NetID | 6 段完整路由标识 | 数据侧清了；**代码侧、测试夹具、文档侧、本书自己**都还留着 |
| 内网地址 | 4 段 | 只以"计数标签"的形态出现在口径里 |

**四档里最刺眼的不是上面任何一档**，而是另一件事：
`data/sidecar_in/` 里混进过一份**未脱敏的原始数据**（9.2 MB），
在**首个提交**就入库了——它带真实主机路径、真实墙钟、32 处完整 NetID；
而 `data/raw/` 里那份是脱敏后的母本。

**也就是说：本仓对外发出去的是没脱敏的那一份。**

于是本卷写在这一章里的"已执行 2026-10-22"，
以及收尾文档里"C1 脱敏已清偿"那句话，
**在发布出去的那个仓里是假的**。
账是照着**工作树**记的，而对外发的是**跟踪文件**——
两者不是一回事。

这一节要教的就一件事：

> **"我清过了"必须对着"我发出去的东西"清。**
> 清完本地、清完工作树，然后问一句：
> **发布出去的那一份，干净吗？**

现在 `data/probe_pii.py` 扫的是 `git ls-files` 的结果
（= 会被发布出去的那些），五档值任一非 0 就 `exit 1`，
CI 的「脱敏自检」这一步因此会**真的红**。
顺带把它的退出码补上了——**此前它只打印不判定**：
值类 token 不为零，CI 也不会红。

**没被门抓到的那一类，也要说清楚**：
token 门是**字面匹配**，它抓不到"用别的写法写的同一个主机名"；
而按 KB2 §六，**署名与 DOI 绝不清除**
（通讯作者的邮箱是法定义务的一部分）✓

## 8.6 事实来源纪律：抽取式优先于手读

KB2 §4 末尾有"事实来源纪律"一节
（`docs/kb/KB2-waveform-formats.md:658`），里面第 6 条是
（`docs/kb/KB2-waveform-formats.md:683-685`）：

> **抽取式核对优先于手读**。凡厂商工件或数据集原始文件里
> **可机器抽取**的字段，一律由抽取脚本重生成，**禁止凭记忆书写**。

这条与第 3 章 KB0 检查 27（`docs/kb/KB0-conventions.md:304`）
是同一件事的两面：
**凡"全量实测 / 行级差异数 / 恒等式成立或证伪"类断言，
须指向本仓一个可重跑产物**。

**"抽取式"和"手读"的区别在信任等级上**：

- 手读：人看过一遍，写下"大概是 18650 行"；
- 抽取式：脚本跑过，写下 18650，而且**明天还能再跑一遍得到同样的数**。

KB2 §1.1 的解剖就是抽取式的产物
（`docs/kb/KB2-waveform-formats.md:43-59`）：
`Export10_244531.csv` = **32 通道 / 64 列 / 18650 数据行**；
表头 **13 行**；总时长 ≈ **18.65 s** = 18650 行 × 1 ms（**自洽**）。

"自洽"两个字是关键：18650 × 1 ms = 18.65 s，
和文件里声明的总时长对得上。
**一个数如果和另一个独立来源的数对得上，它就更可能是真的。**

还有个细节（`docs/kb/KB2-waveform-formats.md:72-75`）：
取列规则是 `names` 取第 7 行的奇数列，`value_col(k) = 2*k+1`，
`t = col0 * dt_ms / 1000`。

**按列位置索引取数，绝不按名字字符串匹配取数**
（`docs/kb/KB2-waveform-formats.md:86`）——
这条听起来是实现细节，其实是**正确性**问题：
名字可能重复、可能变、可能是本地化过的；
位置是那个文件的**结构事实**。

## 习题

   可复算靠 DOI + 抽取脚本。这个取舍让"可复算"多了哪个前提？

   本仓的 `probe_darus_provenance.py` 是全仓唯一联网脚本
