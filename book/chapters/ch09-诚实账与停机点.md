## 9.1 概念：诚实账不是自我批评，是工程资产

绝大多数项目的收尾文档长这样：
"本项目实现了 A、B、C 共 15 个功能，测试通过，未来将继续完善。"

本仓的收尾文档长这样（`docs/项目回顾与收尾_20261022.md:47-54`）：

> ## 四、诚实账（未结清项，原文在案）
>
> - **脱敏未完成**：发布前必做项尚未执行（README 尾部明示"本仓库当前尚未完成"，
>   命中清单挂 `docs/kb/KB2-waveform-formats.md:527`、`:561`）。
> - **KB7 标题不一致未核**：DARUS-3600 标题存在两条不同逐字串
>   （README §数据来源"未核验"段），需要回源裁决。
> - **Tier C 真机**：离线引擎的全部结论停留在仿真与数据集验证层，
>   真机波次验证未开始——**设计性挂起，不是欠账**。

这段话有三个特征，每一个都是刻意为之：

1. **"原文在案"**——它说的是"这几笔账当时是这么记的"，
   而不是"我们现在觉得没问题"。**不修饰历史**。
2. **每笔账都带**"在哪儿能查"**（`docs/kb/KB2-waveform-formats.md:527`、`docs/kb/KB2-waveform-formats.md:561`、README 段落名）——
   账不是抱怨，是**可定位的条目**。
3. **明确区分"欠账"与"量程边界"**：
   真机波次那条直接写"**设计性挂起，不是欠账**"（`docs/项目回顾与收尾_20261022.md:54`）。

第 3 点尤其重要。**把所有没做的事都叫"欠账"，账就废了**——
因为混在一起的账无法偿还，只能永久挂在那里。
本仓的做法是：能还的还，**不能还的，划到量程边界之外并说明为什么**。

## 9.5 四件套与停机宣告

§五 是"四件套核验（R1，2026-10-22）"
（`docs/项目回顾与收尾_20261022.md:56`），
四件套分别是（`docs/项目回顾与收尾_20261022.md:58-63`）：

| 件 | 状态 |
|---|---|
| 同步文档 | ✅ 本文件 |
| 处置未提交 | ✅ 收尾前 0 未提交（`d5717fb`）；收尾 commit 后仍 0 |
| 决策清单 | ✅ `forensics-learning-book/decision-lists/axiscope-<停机点>.md`（书仓归档） |
| 明确停机点 | ✅ 本文件入库 commit；真机层设计性挂起 |

**"四件套"这个提法本身就是一条纪律**：
一个项目要停，得同时满足四件——有同步文档、工作区干净、
有决策清单、有明确的停机点 commit。**少一件都不算停**。

§六 是停机宣告（`docs/项目回顾与收尾_20261022.md:65-69`）：

> 自本 commit 起，axiscope 进入停机点：主线契约/知识库/引擎/测试全部入库，
> 后续任何变更走新战役立照，**不在本停机点上叠加**。
> 降级线登记于全局台账（`self-improving/ledger.md`，决策清单索引行）。

**"不在本停机点上叠加"** 是停机宣告里最有价值的一句。
它的意思是：**停机点是一个基线，不是一个终点**。
继续做，就**另起一个战役**、另立一份照，而不是在旧基线上打补丁。

为什么这条重要？因为**在基线上打补丁会让基线失去意义**——
基线的价值在于"这里的每一个数字都有明确日期和明确口径"。
一旦开始在上面随手加东西，"截至某日"这句话就失效了。

### 9.5.1 决策清单：为什么它必须被 vendor 进本卷

决策清单在**另一个仓**：收尾文档把它记在书仓的 decision-lists 目录下
（`docs/项目回顾与收尾_20261022.md:62`；那一行写的是当时的仓名）✓。
**同一份原件现在公开可读**——`forensics-mcopilot` 仓里有一份归档 ✓
（它在那个仓里的仓内路径登记在 `book/evidence/REGISTRY.json` 的 `path` 字段 ✓）。

**这份原件现在公开可读**（forensics-mcopilot 仓已推送 ✓）——
所以「读者点不开」这个理由已经不成立了。
但**本卷仍然把它 vendor 进来**，理由换了一条，而且更硬：

**坐标要自足。** 读者只 clone 本仓，就能核到本卷的每一个坐标；
不必再 clone 第二个仓、也不必指望那个仓一直在。
仓外原件会搬家、会撤下、会改；而**门禁要在只有本仓的环境里自证** ✓。

所以规矩不变：**引用一个仓外文件，就必须把原件 vendored 进来**，
并在 `book/evidence/REGISTRY.json` 里登记**指针 + size + sha256**。
登记的 sha256 算的是**仓库内容（blob）**，不是工作区文件——
两仓都开了 autocrlf，工作区是 CRLF，直接哈希工作区文件会得到另一个哈希 ✓。

本卷据此 vendored 了该决策清单（`book/evidence/`），
登记项见 `book/evidence/REGISTRY.json`。

**这是本书能公开的前提**：坐标审计器认得它，
读者下载得到它，sha256 对得上。
**一条坐标如果只有作者自己能点开，它就不是坐标，是内部暗号。**

### 9.6.1 CI 那个既有 bug：三层

**第一层：依赖从来没装。**
runner 上跑 `python -m pytest -q` 直接得到
`No module named pytest`；补上 pytest 之后**还是红的**，
12 个测试模块在收集期就 `ModuleNotFoundError: No module named 'numpy'`。
也就是说**这个仓的 CI 从建起来就没有绿过**，
"403 项当日亲跑全绿"这件事只在本机成立过。

依赖其实登记在案（`docs/kb/KB0-conventions.md:130`：
Python ≥ 3.11，`numpy` + `scipy.signal` 为唯一数值依赖），
只是**登记了不等于装了**——workflow 少一行 `pip install`。
本卷补上了这一行，并且**把版本钉死**
（numpy 2.5.3 / scipy 1.18.1 / pytest 9.1.1，即本地实测通过的那一套）。

**为什么钉版本**：CI 要验的是「实测过的那套版本」，不是「今天能装上的最新版」。
版本一浮，CI 可能因为一次无关的依赖发布而红，而仓里看不出原因——
这正是本仓第 9 章说的那种"没人能解释的红"。

**这件事之所以能一直红着没人发现，恰恰是因为
没人把"CI 是不是真的在跑测试"当成一件要核的事**——
CI 徽章红着，读者以为"项目还没写完"，
作者以为"上次跑过是绿的"。**两边的理解都是对的，合起来是错的。**

### 9.6.2 第二层：控制台编码，崩在打印上

补上依赖之后，CI 到了**最后一步**又红了：
`data/probe_pii.py` 在 runner 上抛

```
UnicodeEncodeError: 'charmap' codec can't encode character '\uff08'
```

`\uff08` 是全角左括号。**runner 的控制台是 cp1252**，
而这个脚本要打印中文表格——于是它**崩在打印上，而不是给出判定**。

这个坑本仓**已经踩过一次**：`data/validate_raw.py:1652` 就有那行房规
（注释写着"Git Bash 控制台默认 cp936，中文报告需强制 utf-8"），
**只是没推广到其余 19 个脚本**。
本卷把房规补齐：每个探针脚本在 import 之后、任何 print 之前，
加上

```python
try:
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")
except Exception:  # pragma: no cover - 环境相关
    pass
```

**为什么必须放在模块级、而不是 `main()` 里**：
模块级 print 崩了，`main()` 里的补救来不及。

**为什么这一层特别值得记**：前两层（缺依赖、缺数值栈）**在日志里一眼能看出来**，
而这一层——**本机是绿的**。本机控制台是 UTF-8，脚本打印正常；
runner 是 cp1252，脚本崩在第一行输出上。
**同一个脚本，两个环境，两个结果，而"本机绿"根本不是证据。**

### 9.7.2 一件**后来做了**的事：把历史里的副本清掉

那份未脱敏的原始数据，在**首个提交 `d5717fb`** 就进了 git 历史。
本卷把它从分支尖端取消了跟踪、也从工作区删了，
但**历史里的那一份还在**——`git clone` 仍能取到。

本卷一开始**没有做**这一步，理由记在书里（"要清需要什么代价"）：
改写历史会毁掉每个提交的 SHA，而本仓的坐标体系正建立在 SHA 上；
强推一个已公开仓的历史，是**不可撤销**的动作。

**后来做了**——用 `git filter-repo` 重写全部历史：

| 做法 | 清掉了什么 |
|---|---|
| `--invert-paths` 删掉那个路径 | 那份 9.2 MB 未脱敏副本，**连同它在历史里的每个版本** |
| 逐条替换历史 blob 里的标识原值 | 不只是那个文件——**凡是历史里出现过的** NetID / 内网地址 / 主机路径 / 绝对墙钟，一律令牌化 |
| 提交信息里的 SHA 引用 | 自动改写成改写后的新 SHA |

**代价，逐条记清楚**：

1. **每个提交的 SHA 都变了**（16 个提交 → 16 个新提交），
   连带书卷的**坐标锚**也变了（`7f7c37e`）；
   书里所有锚点引用与 SHA 引用**全部跟着换**，
   `book/tools/_anchor.py` 是唯一一处真源 ✓，其余由结构门禁核对 ✓。
2. **"当时的样子"没了**。锚点本来是用来钉住"发现当时"的；
   改写之后，**锚点里的原值也一并被清掉了**——
   现在坐标指得到那一行，但那一行已经是令牌化后的样子。
3. **已 clone 过的人手里仍有一份**。改写只管"从这个远端再 clone"，
   管不了别人本地已有的副本。
4. **强推是不可撤销的**。这一步做完就没有回头路了——
   所以本卷先做了完整备份，并把备份在推完之后销毁
   （备份本身就是一份未脱敏副本，留着就是新的历史债）。

**这一节真正要教的事，是顺序**：

> **要改写历史，就先把要留存的原样留下来。**

本卷的顺序是：先 **vendor**（收尾决策清单逐字快照 + sha256 登记，
早就在册 ✓）→ 再**改写**（本次）→ 再把**坐标锚搬过去**（本次）。
反过来做，那份快照就没了。

`book/evidence/` 里那份快照里也提到过旧 SHA，它随改写失效了——
但**快照本身一字未动** ✓（改了它，证据链就断了）：
**快照的固有性质就是"它记录的是那个时刻"**，
它引用的旧 SHA 失效，不是快照的错，是历史的错。

**最后那一条护栏是这条机制能成立的关键。**
没有它，这张登记表半年后就会变成一张没人看的白名单，
工具也就只剩"看起来在查"这一层了。
**一个能被登记的例外，必须同时被登记、被披露、被复核——三样缺一，例外就变成了漏洞。**

这也从反面说明了一件事：
**门禁的价值不在于它抓到了什么，而在于它抓到的东西必须有人处理。**
一个报了警、然后被悄悄加进白名单的门禁，
比一个从来没报过警的门禁更危险——
因为后者至少还诚实地说自己没查出来。
