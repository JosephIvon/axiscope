## 5.1 概念：三层不是目录结构，是"谁可以知道什么"

先说清楚：**三层不是代码组织偏好，是一条可测性的设计**。

依赖图（`docs/wiki/01-overview.md:57-66`）：

```
          twincat ── dialects ── mapping ── c1 ──── features
            （接入层：只认文件形态与列语义，不知道"故障"为何物）
                       anchors（叶子：稳定锚形状，防成环共用）
                            │
     rule_table.json ── registration ── engine ── core_hash
            （归因层：判据求值、门与账目、置信度、排序与哈希）
          confidence ──┘        c3validate ──┘
     assertions ── report ── __main__
            （校验与呈现层：复算报告、渲染 HTML、编排 CLI）
```

Wiki 特别注明这张图**不是画着好看的**——
"要点（均从 import 语句实测）"（`docs/wiki/01-overview.md:68`）。

三条实测出来的纪律（`docs/wiki/01-overview.md:70-73`）：

- **单向依赖**：接入层不 import 归因层；`features` 不 import `engine`；
  `c3validate` 读 `core_hash`/`confidence`/`anchors` 做独立复算，
  `engine` 也读同一批实现——**"落码侧与复算侧不得各自发明"靠 import 同源保证**。
- **防环手法**：`twincat.read_scope` 对 `dialects` 用**函数内延迟 import**；
  `anchors` 是无人依赖它的叶子模块。
- **第三方依赖只有两个**：`numpy` 与 `scipy.signal.welch`；`synth` 另用 `scipy.linalg.expm`。
  校验/报告/归因层**全部是标准库**；`matplotlib`、`pandas` 在代码中 **0 处 import**。

"防环手法"这一条值得多说一句：`twincat` 与 `dialects` 互相知道对方
（一个要判断"是不是 Scope View"，一个要回退去读别的方言），
但直接互相 import 就会成环。解法是**把 import 挪进函数体**——
它在调用时才解析，运行期不成环。
这不是技巧，是**为了能在两页纸内表达这个依赖**而付的代价。

**"0 处 import matplotlib/pandas"** 这条也有实际意义：
读者要复算一条结论，装两个库就够（`docs/wiki/01-overview.md:72`）。
第 8 章讲数据时还会回到这条。

## 5.2 接入层：把文件读成结构化表

接入层覆盖 `twincat.py`、`dialects.py`、`mapping.py`、`c1.py`，
它的承诺写在一行里（`docs/wiki/02-integration-layer.md:3`）：

> 这一层的承诺是「只把文件读成结构化表并装进 C1 契约包」，
> **不认识故障、不做诊断**。

**"不认识故障"是一条纪律，不是修辞**。
如果 `twincat.py` 里出现"这个通道看起来像电流"这种判断，
那这条判断就同时污染了两件事：解析的正确性和诊断的结论。
第 2 章说过 C1 要求"任何超出契约的推断一律不写进包，
改写进 `meta.audit.assumptions`"（`src/axiscope/c1.py:3`），
接入层就是这条纪律的**第一道执行点**。

### 5.2.1 `twincat.py`：D1 读表器与"宁可拒读"

`read_scope(path) -> ScopeTable` 是公开入口（`docs/wiki/02-integration-layer.md:11`），
它的 docstring 原文口径是：
「只做『读成结构化表』这一件事，语义映射在 mapping.py，契约装包在 c1.py」。

`ScopeFormatError` 有**四个抛出点**（`docs/wiki/02-integration-layer.md:12`）：

- 无 `Name` 表头行；
- 表头列数为奇数（非键值交替）；
- 通道名重复；
- 通道含非数值单元。

异常的口径是"**结构定位失败：宁可拒读，不得按猜测解析**"。

注意这四条全是**结构性**的，不是"数值好不好看"——
这和第 2 章 C1 的红线是两类：红线管**数据质量**，
这里管**文件形态**。形态不对，样本连"包"的边都进不去。

`ScopeTable` 这个 dataclass 字段很长（`docs/wiki/02-integration-layer.md:14`），
其中有四个槽**只由 dialects 填**：`dialect`、`time_column`、
`time_col_source`、`unit_source`。
这四个槽是"这条记录是哪条路读出来的"的痕迹。

### 5.2.2 `dialects.py`：时间轴是唯一硬门槛

`dialects.py` 的 docstring 口径是：**只回答三件事**——
有哪些列、每列多少行、时间轴从哪来
（`docs/wiki/02-integration-layer.md:22`）。

而**时间轴是唯一硬门槛**：ISO 文本列 → epoch 秒；
列名带单位 → `column_name:<unit>`；
否则只认同名侧车 `<file>.source.txt` 的 `sampling_rate` 声称，
且"有且仅有一种"单位假设能复现 → `sidecar_attested:<unit>`；
**都不成立 → 拒读**（D4 形态）。

四个方言常量（`docs/wiki/02-integration-layer.md:34-39`）：
`tsv_iso8601`、`semicolon_european_decimal`、`csv_iso8601_rowindex`、`csv_segment_index`。

### 5.2.3 D1–D6 与 `dialect` 字段：一张实测表

Wiki 里有一张表，把台账编号 D1–D6 与**代码里真正的载体**对上
（`docs/wiki/02-integration-layer.md:45-50`），并注明每格都来自现跑核对
（`data/probe_dialects.py` 全量输出 + `tests/test_export_dialects.py` 的逐条断言）。

其中一个格子很值得注意——**D4 没有 dialect 值**：
`_resolve_time_column` 失败即抛 `ScopeFormatError`，
**发生在赋值之前**，所以产物里根本不存在 D4 的方言字符串。

这是"编号只是台账记法，产品载体始终是 `dialect` 字段字符串"的最好例子
（`docs/wiki/02-integration-layer.md:45`）。
第 3 章讲过 slug 是接口、显示名是渲染；这里是同一条原则的另一个侧面：
**台账编号是记录，产品字段才是契约**。

### 5.2.4 `mapping.py` 与 `c1.py`：装包

`mapping.py` 里有 `MAPPED`（恰 3 条）、`EXTRAS`（29 条）、
`CROSS_VALIDATION_PAIRS`（3 对）等
（`docs/wiki/02-integration-layer.md:62-65`），
`check_coverage(header_columns)` 抛 `AssertionError`（`docs/wiki/02-integration-layer.md:66`）。

`c1.py` 的关键常量（`docs/wiki/02-integration-layer.md:72`）：
`SCHEMA = "axiscope.waveform/1"`、`VOCAB_ORDER` 恰 **14** 个 canonical 通道、
`SEGMENT_KINDS` 10 种、`CITATION`（DARUS-3600, DOI 10.18419/DARUS-3600）、
`IDENTITY_REL_TOL = 1e-12`、`AUDIT_IDENTITY_KEYS` 8 键。

`write_pack` **只写两个文件**并返回 `{"dir","sha256","n_rows","n_cols"}`
（`docs/wiki/02-integration-layer.md:77`）——
`sha256` 是 waveform 字节与 meta body 的**联合哈希**。

**为什么是联合哈希**：因为"波形对但元数据错"和"元数据对但波形错"一样是坏包。
分开哈希的话，校验方得自己决定拿哪个对；联合哈希让"这个包是不是这个包"
变成**一个可传递的判断**。

## 5.3 特征与归因层

`features.compute(meta, ingest, pack_dir)` 是特征层的入口
（`docs/wiki/03-analysis-core.md:7`），
`ingest_profile == "dialect_generic"` 时走 `_compute_generic`（`docs/wiki/03-analysis-core.md:7`）。

两个必须知道的机制（`docs/wiki/03-analysis-core.md:20`）：

- **频带门禁**：超出可靠频带的判据不许出结论，只许记 blocked；
- **null 账目**：算不出写 `null` 并同步追加 `unavailable`。

`confidence.py` 是 **KB4 §2.1/§2.2 的权威实现**（`docs/wiki/03-analysis-core.md:24`），
`registration.Ledger` 是登记层（门与账目）（`docs/wiki/03-analysis-core.md:49`），
`engine.analyze(features, meta=None, source_tier=…, case_id=…)` 是编排
（`docs/wiki/03-analysis-core.md:57`，13 步序列），
`core_hash.py` 是 C3 规则 21 的哈希核（`docs/wiki/03-analysis-core.md:73`）。

第 6 章整章讲这层的数学。

**这里有一条容易踩的坑**，Wiki 专门辟了段
（`docs/wiki/03-analysis-core.md:43`）：**"9 个规则族"这个说法不准确**——
9 是条目数，而 `leaf.family` 实际只出现 3 个值
（`mechanical_resonance` / `electrical_feedforward_mismatch` /
`software_induced_interp_buffer_underrun`），其余 5 条 `family = null`
（1 条门禁、2 条仲裁、2 条 meta）。

**已知文档漂移**第 3 条记的就是这件事（`docs/wiki/07-run-guide.md:84-88`）:
本仓有一条"如实在册"的漂移清单，不掩饰。

## 5.4 校验与呈现层：两层自检的分工

`c3validate` **只做结构/数值/措辞判定，不调 LLM、不联网**
（`docs/wiki/04-validation-report-cli.md:7`）；
唯一例外是规则 17/18（`docs/wiki/04-validation-report-cli.md:7`）。

`assertions.run(...)` 检的是**接入与特征产物**（样本包、特征包），
判定源是 KB2 §8.3 断言集 + **磁盘复读**（`docs/wiki/04-validation-report-cli.md:29`）——
注意"磁盘复读"：断言不信内存里的对象，它**重新读一遍产物文件**再判。

两层自检的分工（`docs/wiki/04-validation-report-cli.md:49-54`）：

| 层 | 对象 | 判定源 | 失败语义 |
|---|---|---|---|
| `assertions.run` | 接入与特征产物 | KB2 §8.3 断言集 + 磁盘复读 | 计入退出码 1 的 FAIL |
| `c3validate.validate` | 诊断报告 `diagnosis.json` | C3 契约 21 条硬性规则 + KB4 不变式 | 计入退出码 1 的 C3 FAIL；`C3-R14` 可升级为拒收异常 |

`assertions.run` 共有 **24 条**不同名断言（25 个调用点）
（`docs/wiki/04-validation-report-cli.md:27`），
`C1_VOCAB` 恰 14 个通道名（`docs/wiki/04-validation-report-cli.md:28`）。

`anchors.py` 提供 `ANCHOR_FORMS` 六种合法锚、`anchor_kind()`、
`assumption_row(anchor, statement)`、`AnchorNotStable`
（`docs/wiki/04-validation-report-cli.md:34`）——
这就是第 2 章"锚点必须是六种稳定形式之一"的落码处。

**`report` 没有绘图依赖**，手写 html/io（`docs/wiki/04-validation-report-cli.md:38`）。
这解释了为什么 `matplotlib` 在代码里 0 处 import
（`docs/wiki/01-overview.md:72`）——报告是**纯文本 + HTML**。

## 5.5 CLI：一次运行的完整序列

`__main__.run` 编排的顺序（`docs/wiki/04-validation-report-cli.md:42`）：

```
read_scope → c1.build_meta → c1.write_pack →（回填 sha256/sample_id）
→ features.compute → write_features → 拒收检查
→ engine.analyze → c3validate.validate（结果附入 diagnosis.json）
→ assertions.run → report.write_report → 打印摘要
```

**"拒收检查"卡在 features 之后、analyze 之前**（`docs/wiki/04-validation-report-cli.md:44-45`）：
非 Scope View 方言没有触发门控槽位时，
样本包与特征已落盘，但断言层/报告层**只覆盖 D1 门控样本**，
不造恒真前提，打"拒收"到 stderr，`return 2`。

CLI 参数（`docs/wiki/04-validation-report-cli.md:46`）：
`--in <厂商CSV> --out <样本包目录> [--sample-id]`；
stdout/stderr **先** `reconfigure(encoding="utf-8")`。

## 5.6 动手：跑一次，看它诚实地说"我不知道"

本章动手是**跑通一次完整链路**，并读懂它的输出。

```powershell
cd /d/workspace/axiscope
PYTHONPATH=src PYTHONIOENCODING=utf-8 python -m axiscope --in data/raw/Export10_244531.csv --out build/Export10_244531
```

预期最后两行（`docs/wiki/07-run-guide.md:23-24`）：

```
归因：主假设 None · overall_confidence None · 命中 ['R-30'] · 跳过 14 条
断言 24/24 通过 · C3 契约 71/71 通过
```

**"主假设 None"不是 bug**（`docs/wiki/07-run-guide.md:27`）：
Export10 的可用证据不足以过 §2.1 门，
**诚实真空输出**（`causal_claims_permitted` 恒 false 同）。

这一屏是整个项目**最值得看的东西**：
断言 24/24 通过、契约 71/71 通过、退出码 0——
**但它拒绝给出主假设**。

一个刚跑通的引擎给不出结论，恰恰说明它的门是真的。
第 7 章会看到同一件事在评测侧的样子（`top1_hit = 0`、`ece = null`）。

**再跑一次拒收**，看退出码 2：

```powershell
PYTHONPATH=src PYTHONIOENCODING=utf-8 python -m axiscope --in data/incoming/6114_ObserverTestSet.tab --out build/d4
```

**再跑一次门禁**（第 5 章的重点）：

```powershell
PYTHONPATH=src python -m pytest tests/test_offline_discipline.py -q
```

它静态扫描 `src/axiscope` 与 `synth` 全部模块，不足 10 个文件直接红；
禁 `socket`/`urllib`/`httpx`、`openai`/`anthropic`/`langchain`、
`torch`/`sklearn` 三类 import 与 `__import__`/`importlib.import_module`/
`eval`/`exec`/`compile`/`os.system`/`os.popen` 动态逃逸
（`docs/wiki/05-toolchain.md:43`）；
另含 CLI 两档退出码例（D4 拒收 2 且无 Traceback、D1 正常 0）。

**动手验收**：你能指着"主假设 None · overall_confidence None"这一行，
说出它**证明**了什么、**没证明**什么。

## 习题

1. 依赖图里 `twincat` 对 `dialects` 用**函数内延迟 import**
   （`docs/wiki/01-overview.md:71`）。如果改成模块顶部 import 会发生什么？
   为什么作者宁可付这个代价？
2. `write_pack` 的 `sha256` 是 waveform 字节 + meta body 的**联合**哈希
   （`docs/wiki/02-integration-layer.md:77`）。
   如果拆成两个哈希，会丢掉哪一种检查能力？
3. `ScopeFormatError` 的四个抛出点（`docs/wiki/02-integration-layer.md:12`）
   全部是**结构性**的。挑一个，说明它挡住的是哪一类"看起来能用"的数据。
4. D4 没有 `dialect` 值（`docs/wiki/02-integration-layer.md:45`）。
   如果给它编一个 `"unknown"` 值，会有什么后果？
5. `assertions.run` 用**磁盘复读**判定（`docs/wiki/04-validation-report-cli.md:29`），
   而 `c3validate` 判内存里的诊断对象。这两条判定的**失败后果**有什么不同？
   为什么一个要复读、一个不复读？
