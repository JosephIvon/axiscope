## 4.1 概念：知识库管"判据"，外部证据管"事实"

第 3 章的知识库回答"**怎么判**"。但判据再严密，
也不能自己证明"某台伺服驱动器的第 3 根线是什么"。

那类事实只能从**外部**来。而"从外部来"这件事有非常不同的可信度：

- 我在**厂商手册 PDF** 里亲眼看到了这一行；
- 厂商 FAE **书面回复**确认了这一行；
- 同事**口述**过这一行；
- 我**记得**这一行（模型记忆、网上见过、类似产品是这样）。

这四种在报告里的分量天差地别。所以本仓给它建了一条独立的轴
（`docs/kb/KB0-conventions.md:72`），
字段权威名 **`external_reference`**（A-89）。

## 4.2 三条轴：三件正交的事

KB0 把三者的关系写得很明确（`docs/kb/KB0-conventions.md:105`）：

> 上表管"数据来自哪一层"（`source_tier`），
> `external_reference` 管"接口事实从哪知道的"，
> `basis` 管"改进量靠什么立住"。

**三者是正交的**，这是本节的关键：

| 轴 | 回答的问题 | 值域 |
|---|---|---|
| `source_tier` | 数据本身有多硬？ | T1-a / T1-b / T1-c / T2 / T3 |
| `external_reference` | 这个**接口事实**从哪知道的？ | memory / public-doc / official-artifact / vendor_reply / 真机行为 |
| `basis` | 这个**改进量**靠什么立住？ | simulation_validated / rule_heuristic / unverified |

举个具体例子："Kff 前馈增益是 1.5"这句话——
它的 `source_tier` 可能是 T1-a（数据来自 DaRUS 真机采集），
它的 `external_reference` 可能是 `official-artifact`（来自 XML 里的控制器参数），
而"按它调参能改善 62%"这句话的 `basis` 可能是 `rule_heuristic`。

**一句话里塞三个轴，是本仓报告最容易出错的地方**，
也是第 2 章那条"叙述层措辞不得强于 `source_tier`"
（`docs/contracts/C3-diagnosis.md:1003`）存在的原因。

## 4.3 五档来源与"缺行按最低档"

`external_reference` 的五档（`docs/kb/KB0-conventions.md:79-85`）：

| 档 | 含义 | 能不能进对外表述 |
|---|---|---|
| `memory` | 无人核对、凭模型记忆书写 | **禁用**——只能写"待核对" |
| `public-doc` | 公开资料（网页、公开 SDK、第三方会话转述） | 只能作线索 |
| `official-artifact` | 官方工件（手册 PDF、官方 SDK 绑定、配置文件） | 可作接口事实 |
| `vendor_reply` | 厂商书面答复（含日期与适用型号） | 可作接口事实 |
| 真机行为 | 自己在设备上测出来的 | 最强 |

其中 `memory` 那一行写得最重（`docs/kb/KB0-conventions.md:81`）：

> **未标档的接口断言默认按此档处理**（A-71 的缺行按最低档）。

这条叫 A-71。它管的是**默认方向**：
没写来源的断言，默认是**最不可信**的那一档，
而不是"大概是真的"。

同一格里还留了一句刺眼的归因
（`docs/kb/KB0-conventions.md:81`）：**GLM 代码工厂的四条承认全部落在这一档**。
第 4.6 节讲这件事。

## 4.4 降级纪律：外部会话的报告只算 public-doc

本仓做过三份外部会话的核查报告：
`docs/AUDIT-minimax-mcopilot.md`（minimax 轮）、
`docs/AUDIT-minimax-round3.md`（minimax 第三轮）、
`docs/AUDIT-glm-code-factory.md`（GLM 系代码工厂）。

核查的结论之一是：**别人的报告对本仓只是 `public-doc`**。
minimax 第三轮那份附录里的"已确认项"表，
在本仓这边**必须降级标注为 `public-doc`**
（`docs/AUDIT-minimax-round3.md:79`）。

GLM 那份的结论更尖锐（`docs/AUDIT-glm-code-factory.md:82`）：

> GLM 系 代码工厂 | 分层代码生成 + 编译验证 | 真编译真运行，但跑的是虚拟控制器 |
> 签名无外部锚点；核对清单自我生成；"全品牌 PASS"实为 Virtual |

以及它给出的**通用诊断**（`docs/AUDIT-glm-code-factory.md:86`）：

> minimax 用自己的规则判自己，GLM 用照代码生成的清单判代码，

这句话不只适用于那两家的产品。**它也是本书第 2 章那句
"落码侧与复算侧不得各自发明"（`src/axiscope/core_hash.py:3-5`）的通用版本**：
自己生成清单、自己执行、自己判分——这套闭环里没有外部锚点，
它的"PASS"只证明"程序按自己的预期运行"。

### 4.4.1 三条不得越级的线

1. **不把第三方转录的 SDK 签名当事实来源**（`docs/kb/KB2-waveform-formats.md:662-665`，
   A-32）。外部智能体的适配器把某个 SDK 的函数签名抄了一遍，
   那抄本对本仓只是线索。
2. **叙述强度不得高于数据层 tier**（`docs/kb/KB2-waveform-formats.md:676`，A-31）。
3. **对外可转发的口径是**"我们按公开资料形成了下表，请厂商指出不符项"，
   而不是"已确认"（`docs/kb/KB2-waveform-formats.md:673`）。

第 3 条是全章最实用的一条：它把"我们还没核对"翻译成了
**一句可以发出去、且不必收回的话**。
这比含糊其辞的"部分信息待确认"强得多——
后者既不能催对方干活，又给自己留了"其实我确认过"的空间。

## 4.5 升格：两个方向，各有各的门槛

`public-doc` 想升格，KB2 把入口分成**两路**
（`docs/kb/KB2-waveform-formats.md:688-694`）：

- **接口事实类**只需 `official-artifact`；
- **现场/批次类**才需 `vendor_reply`。

两路的门槛都写在各厂商的接入卡上。以 Beckhoff 一张卡为例
（`docs/kb/KB2-waveform-formats.md:417`）：

> **要升格需要什么**：厂商手册 PDF 的具体页码/表号 + 存证文件路径
> （入包内 `raw/` 或 `docs/evidence/`）+ 厂商 FAE 书面确认；
> 三者齐备前，本卡签名/参数条目一律维持 `public-doc`。

雷赛（`docs/kb/KB2-waveform-formats.md:427`）与正运动（`docs/kb/KB2-waveform-formats.md:437`）两张卡的措辞几乎一致——
**这说明它是模板，不是临时发挥**（模板本体在
`docs/kb/KB2-waveform-formats.md:367-372`，九项字段结构）。

注意门槛里有**存证文件路径**这一项：光说"手册上写了"不行，
得把**手册本身放进仓里**（或指到仓内某处）。
理由和第 2 章"派生件哈希只是自证"（第 8 章展开）一样：
**没有存证，凭什么复核**。

还有一条配套纪律（`docs/kb/KB2-waveform-formats.md:683-685`）：

> **抽取式核对优先于手读**。凡厂商工件或数据集原始文件里**可机器抽取**的字段，
> 一律由抽取脚本重生成，**禁止凭记忆书写**。

## 4.6 复用标注：谁的东西，写谁的

这是本章的另一半，也是最直接关系到**著作权诚实**的一节。

归属纪律的原文（`docs/AUDIT-minimax-mcopilot.md:72`）：

> 3. **归属纪律**：复用部分必须在 README 与作品集中标注来源，
> 不得以"我写的"呈现。

README 把它整节兑现了——§7「复用设计标注（非本项目原创的部分）」
（`README.md:83`），义务来源逐字引在 `README.md:85-86`，
表格在 `README.md:88-99`。

逐行读这张表（`README.md:88-99`）：

| 复用的设计 | 落点 | 标注 |
|---|---|---|
| 接入卡**九项字段结构** | KB2 §4 | `docs/kb/KB2-waveform-formats.md:369-371`：「该九项字段结构参考第三方智能体（minimax）…」，**非本项目原创** |
| **七段 jerk 受限 S 曲线**轨迹生成器 | KB5 §4.1–§4.2 | `docs/kb/KB5-simulation-plant.md:793-805`：「**参考来源（设计思路，非代码）**」 |
| `events.jsonl` 的 `source` 词表与判据雏形 | C6 | `docs/AUDIT-minimax-mcopilot.md:59`：「借鉴设计，**不采信其检出率**」 |
| 上位机代码规范的漏乘当量数据流检查 | 代码规范类条目 | `docs/AUDIT-minimax-mcopilot.md:60`：「借鉴，非核心」 |
| 六个**软件诱导缺陷形态** | KB3 / C3 | `docs/kb/KB2-waveform-formats.md:…` |

三处措辞值得逐字读：

- **「非本项目原创」**——直接写在表里；
- **「设计思路，非代码」**——区分了"抄了思路"和"抄了代码"，
  这两者的法律与伦理性质完全不同；
- **「借鉴设计，不采信其检出率」**——**借方法，不借成绩**。
  这一句是复用标注里最讲究的一句：
  别人的方法可以学，但对方的性能数字**不能挂到本项目头上**。

**"不采信其检出率"同时也是一条对自己项目的约束**：
如果本仓的评测集里某个案例的"正确答案"是从别人的结论里抄的，
那这个案例的证明力就打折了——这正是 A-88 的应用
（`docs/kb/KB0-conventions.md:205`）：

> 同源核对物对其自身来源的**正确性证明力记 0**；
> 每类核对物须声明 `source_independence ∈ {external, same_origin}`。

`source_independence` 这个字段把"这份核对物是不是自己产的"
变成**可填的字段**，而不是靠自觉。

## 4.7 动手：给一句话标三轴

本章动手只有一件事：**给一条断言标三轴**。

**第一步**，挑一句你项目里（任何项目里）的断言，例如：
"该驱动器的电流采样周期是 250 μs"。

**第二步**，填表：

| 轴 | 你的填写 |
|---|---|
| `source_tier` | ？ |
| `external_reference` | ？ |
| `basis` | ？ |

**第三步，自查三条**（`docs/kb/KB0-conventions.md:105`、`:81`、`:81`）：

1. 三个轴有没有混用（比如把"我记得"填成 `official-artifact`）？
2. 如果 `external_reference` 那一栏**你没填**——
   按 A-71，它是不是应该按 `memory` 处理？
3. 你写进报告的**措辞**，有没有超过 `source_tier` 允许的上限？

**第四步（进阶）**：把这句话的措辞改成
"我们按公开资料形成了下表，请厂商指出不符项"那种口径
（`docs/kb/KB2-waveform-formats.md:673`），
看它是不是立刻变得**可发送**而不必收回。

**动手验收**：你能对一条具体断言说出三轴各是什么，
以及"缺一档"时它会默认落到哪一档。

## 习题

1. `source_tier` / `external_reference` / `basis` 三轴（`docs/kb/KB0-conventions.md:105`）
   各举一例"填错会怎样"。
   特别地：`source_tier = T3` 但 `external_reference = official-artifact` 的组合合法吗？
2. KB0 那行"GLM 代码工厂的四条承认全部落在这一档"
   （`docs/kb/KB0-conventions.md:81`）说的是哪一档？
   为什么"四条承认"比"一条承认"更值得警惕？
3. "借鉴设计，不采信其检出率"（`docs/AUDIT-minimax-mcopilot.md:59`）：
   如果把别人的方法学了、但用自己的数据测出更好的数字，
   该怎么标注？如果把自己的方法用在自己的数据上、数字还更差呢？
4. 接入卡"要升格需要什么"的三项门槛
   （`docs/kb/KB2-waveform-formats.md:417`）里，
   哪一项最难满足？它难在**技术**上还是**成本**上？
5. A-88（`docs/kb/KB0-conventions.md:205`）要求声明 `source_independence`。
   本仓自己的 KB、契约、测试，相对于"本仓的引擎"算 external 还是 same_origin？
   这个答案会推出什么结论？
