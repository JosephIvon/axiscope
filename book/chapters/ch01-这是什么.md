# 第1章 这是什么

**本章承接**：全书第一章，先把话说清楚——这个项目**是什么**、**不做什么**、
以及它凭什么敢在工业现场说自己可信。

**学完你会**：能用一句话说清 axiscope 的边界（做什么、不做什么），
能指出它把"安全"写在了哪一行代码上，能解释退出码 0/1/2 三档各自意味着什么。

**前置**：会读 Python 与 Markdown；不需要硬件、伺服或产线。

**素材坐标**：`docs/wiki/01-overview.md`、`docs/contracts/C3-diagnosis.md`、
`docs/DECISION-2026-10-19-方向裁决.md`、`docs/项目回顾与收尾_20261022.md`、
`src/axiscope/__main__.py`（锚点 `axiscope@7f7c37e`）。

> **可验证主张**：axiscope 是一个**离线**的伺服/过程波形接入、确定性特征抽取、
> 规则归因与契约自检引擎（`docs/wiki/01-overview.md:8`）：它吃厂商导出的波形文件，
> 吐样本包 → 特征包 → 诊断报告 → 人读的 HTML（`docs/wiki/01-overview.md:10-11`）；
> 它**永不**向真机下发参数——`safety.writes_to_device` 恒为 `false`、
> `requires_human_approval` 恒为 `true`，而且这两条是**契约硬性规则**、
> 由校验器强制，不是口头承诺（`docs/contracts/C3-diagnosis.md:969`）；
> 它的合法性根基是一条被明文裁决过的判断：
> **"录下来的波形就是闭环反馈的完整记录"**
> （`docs/DECISION-2026-10-19-方向裁决.md:21`）；
> 它的进程级合同是**三档退出码**：0 全过 / 1 有 FAIL / 2 拒收
> （`docs/wiki/01-overview.md:75`）。

**已验算**：本章所有坐标按锚点 `axiscope@7f7c37e` 读源文件，由
`book/tools/audit_coords.py` 机器复核；退出码三档在 2026-10-24 于
本机 Python 3.14.8 实跑确认（见 §1.6）。

## 1.1 概念：一个只读波形、不碰机器的诊断引擎

先把边界画出来，再谈能力。axiscope 的自我描述只有一句
（`docs/wiki/01-overview.md:8`）：

> **axiscope 是一个离线的伺服/过程波形接入、确定性特征抽取、规则归因与契约自检引擎。**

这句话里每个限定词都是义务，不是修饰：

| 词 | 它排除了什么 |
|---|---|
| **离线** | 排除在线闭环自整定、排除任何写回真机的路径 |
| **接入** | 它做的是"把厂商文件读成结构化表"，不是"猜这是什么设备" |
| **确定性** | 同一份输入必须给出同一份输出；数值链上没有模型调用 |
| **规则归因** | 结论由**规则表**求值而来，不由模型生成 |
| **契约自检** | 产物要能被自己的校验器独立复算 |

输入与输出各是一条链（`docs/wiki/01-overview.md:10-11`）：

- 输入：厂商运动控制器/示波器的导出文件（首个支持方言是 TwinCAT 3 Scope View 的 CSV）；
- 输出：样本包（`meta.json` + `waveform.tsv`）→ 特征包（`features.json`）
  → 诊断报告（`diagnosis.json`）→ 人读的 `report.html`。

注意输出链的最后一段是 **`report.html`——给人读的**。
报告里的 `field_procedure`（现场操作步骤）也是**人去执行**的
（`docs/项目回顾与收尾_20261022.md:9-11`）。这个项目不代替人操作机器。

## 1.2 合法性的地基：录下来的波形就是闭环反馈的完整记录

这一节是全书唯一一处"为什么这个方向是对的"的论证，所以它必须有出处。

2026-10-19，项目收到三份方向草案，其中一份断言"伺服整定 AI 碰不了"。
裁决书把这句话判死（`docs/DECISION-2026-10-19-方向裁决.md:17`）：

> **裁决：该断言错误，混淆了两件事。**

混淆的是这两件（`docs/DECISION-2026-10-19-方向裁决.md:19-21`）：

- **在线闭环自整定**（无人参与、实时改驱动器参数、带负载）——确实不能碰。
  这是**安全与责任**问题，不是能力问题。
- **离线诊断与参数建议**（从已录制波形出报告）——是纯数据分析。
  而"没有闭环反馈"这个前提是错的：
  > **录下来的波形就是闭环反馈的完整记录。**

这句话是整个项目的地基：有了它，"离线能不能做伺服诊断"这个问题的答案
就不是"能力不够"，而是"根本不是同一个问题"。

裁决同时把**不该碰的**写成了硬约束（`docs/DECISION-2026-10-19-方向裁决.md:9`）：

| 共识 | 来源 | 落点 |
|---|---|---|
| 绝不让 agent 直接下发参数到真机 | A 的"可审核可追溯"、C 的"安全边界" | C3 `safety.writes_to_device=false`、`requires_human_approval=true` |
| 每条结论必须带来源与置信度 | A、C | C3 证据结构 + C5 ECE 指标 |
| 用客观验证取代"模型评判模型" | C 最强的一条 | C4 验证门控 + C5 三层证据 |
| 先冻结契约与评测集，再写 agent | C 结尾 | 当前阶段（P0/P1）不做任何 agent 代码 |

注意最后一行：**契约先行**不是后来补的价值观，
它是 2026-10-19 就写进裁决书的第一条工程纪律（`docs/DECISION-2026-10-19-方向裁决.md:12`），
第 2 章整章讲它怎么落地。

## 1.3 安全边界：写在代码里，不写在 PPT 里

工业项目最不缺的是"我们很安全"这句话，最缺的是**这句话的落点**。
本仓的做法是把它写进契约、再用校验器强制。

C3 契约的硬性规则 6（`docs/contracts/C3-diagnosis.md:969`）：

> **`safety.writes_to_device` 恒为 false**。本智能体永不直接下发参数到真机。

Wiki 把它标成"**代码级承诺，非口头**"，并且点明由校验器的
`C3-R06-writes` / `C3-R06-approval` 两条检查强制
（`docs/wiki/01-overview.md:12`）。也就是说：这条承诺不是写在文档里等人遵守，
而是**写在产物 schema 里、由校验器每次运行都查一遍**。

配套的还有一条**离线纪律**（`docs/wiki/01-overview.md:12`）：
数值链上没有模型调用——`tests/test_offline_discipline.py` 门禁扫描
`src/axiscope` 与 `synth` 的全部模块，禁网络栈、LLM SDK、训练框架 import，
以及 `eval` / `__import__` 这类动态逃逸。

这条门禁的作用是把"离线"从**承诺**变成**可检验的性质**：
哪天有人往分析链里插了一个 `import requests`，门禁立刻变红。

## 1.4 三档退出码：一个进程对外的全部语言

一个工具对外的表达方式就是它的**退出码**。本仓把它定成进程级合同
（`docs/wiki/01-overview.md:75`）：

| 退出码 | 条件 | 出处 |
|---|---|---|
| 0 | 端到端断言与 C3 契约检查全部通过 | `__main__.run` 末行（`docs/wiki/01-overview.md:79`） |
| 1 | 存在 FAIL 断言或未通过的契约检查（产物仍写出，stderr 逐条列） | 同上（`docs/wiki/01-overview.md:80`） |
| 2 | 拒收：`c1.PackError` / `features.FeatureError` / `twincat.ScopeFormatError`，或非 Scope View 方言无 `trigger_gate` 时链路止步 | `__main__.main` 捕获 + `run` 内分支（`docs/wiki/01-overview.md:81`） |

**三档的分工是这门设计的全部要点**：

- **0** = 我处理了这份数据，结论我担保；
- **1** = 我处理了这份数据，**但有一条检查没过**（产物仍然写出，
  失败项逐条打在 stderr 上——**不给结论，也不销毁证据**）；
- **2** = **这份数据我拒绝处理**（拒收分支 A/B）。

**为什么"拒收"必须单列一档**：如果把"我拒绝处理"和"我处理了但有检查没过"
混在同一档，那么调用方无法区分"结论里有错"与"根本没有结论"——
而这两件事该采取的行动完全不同。前者要复查，后者要换数据。
第 1 章这一条，是后面所有章节的接口约定。

## 1.5 依赖方向：单向依赖不是风格，是可测性的前提

仓里有一条硬约束：接入层不 import 归因层；`features` 不 import `engine`
（`docs/wiki/01-overview.md:70`）。这条约束的直接后果是——
**每一层都能被单独测试**，因为下层不知道上层的存在。

```
twincat ── dialects ── mapping ── c1 ──── features      （接入层）
      anchors（叶子：稳定锚形状，防成环共用）             （归因层）
rule_table.json ── registration ── engine ── core_hash
confidence ──┘        c3validate ──┘
assertions ── report ── __main__                          （校验与呈现层）
```

（分层图原样引自 `docs/wiki/01-overview.md:64-69`。）

第三方依赖只有两个（`docs/wiki/01-overview.md:72`）：
`numpy`（恒等式核对与特征数值）与 `scipy.signal.welch`（PSD）；
`synth` 另用 `scipy.linalg.expm`。
**校验、报告、归因层全部是标准库**——`matplotlib`、`pandas` 在代码中 **0 处 import**。

这一条对"可核对"的意义：读者要复算一条结论，
装两个库就够（`docs/wiki/01-overview.md:72`）。

## 1.6 动手：把三档退出码跑出来

本章只有一个动手环节，目的是亲手看见"拒收"与"没通过"不是一回事。

**环境**：Python ≥ 3.11，`numpy` 与 `scipy`（口径记在 KB0）。

```powershell
# 1) 装依赖（两个）
python -m pip install numpy scipy

# 2) 看全量测试当日实跑（本仓的"账面"在第 9 章核）
python -m pytest -q
```

预期：测试全绿。收尾文档记录的是 2026-10-22 当日实跑
**403 passed, 24.71s**（`docs/项目回顾与收尾_20261022.md:4`）——
**注意这是收尾当天的历史事实**，不是"现在的数"；第 9 章会当场把账面与实测对齐。

**看拒收**：拿一份"没有时间列"的导出喂给它（仓内样例：
`data/incoming/6114_ObserverTestSet.tab`），期望看到**退出码 2** 与
"拒收：…"字样，而不是一段 traceback。

**看三档的语言**：`python -m axiscope --in <厂商CSV> --out <样本包目录>`
（参数与编排见 `docs/wiki/04-validation-report-cli.md`）。
退出码 0 时它给结论；1 时它给产物加一份逐条失败清单；
2 时它只给一句拒收理由。

**动手验收**：你能指着一条 `docs/wiki/01-overview.md:79-81` 说清
"0/1/2 分别意味着我该不该信它"。
