# OUTLINE —— 本卷规格

> 本文件是**规格**，不是目录：它规定每一章必须交付什么、
> 坐标必须长什么样、什么情况下这一卷算完成。
> 正文在 `chapters/`，裁剪件在 `crops/`，工具在 `tools/`。
> **规格变了，正文必须跟着变**——所以本文件与正文由同一批门禁守着。

---

## 一、卷的定位

| 项 | 内容 |
|---|---|
| **对象** | axiscope（离线伺服/过程波形诊断与归因引擎），**公开仓** |
| **锚点** | `axiscope@7f7c37e`（由 `tools/_anchor.py` 单点定义） |
| **读者** | 现场工程师 / 平台开发者 / 审核尽调 / 讲师 |
| **不是** | 使用手册、技术规格书、宣传材料 |
| **是** | 可复核的工程解剖：每条事实挂坐标，每条坐标可解析 |

## 二、章的规格

**九章**，每章固定交付十一件（由 `tools/check_book_structure.py` 判）：

| # | 件 | 要求 |
|---|---|---|
| 1 | 标题 | `# ` 开头 |
| 2 | 本章承接 | 在**章首 12 行内**（不许读者翻半页才知道这章接什么） |
| 3 | 学完你会 | 可检验的动作，不是"了解…的重要性" |
| 4 | 前置 | 依赖哪几章 |
| 5 | 素材坐标 | 本章用到的仓内材料 |
| 6 | 已验算 | 本章哪些数字是**实跑**出来的 |
| 7 | 证据与坐标 | `## 证据与坐标` 区：材料 / 坐标 / 用途 三列 |
| 8 | 可验证主张 | 一句带坐标、可当场复核的主张 |
| 9 | 讲师切分 | `**讲师 90 分钟**` 表 |
| 10 | 习题 | 每题都要**引用具体坐标**作答 |
| 11 | 本章事实性句子坐标 | 逐条列出，供坐标审计器解析 |

**禁项**（扫描判失败）：

- **会话坐标**（"上文提到""前面说过"）——读者手里只有一本书，没有对话；
- **裸行号坐标**（`（`:26`））——`:26` 是哪个文件的第 26 行？**一律写全路径**。

## 三、坐标的规格

```
`docs/kb/KB0-conventions.md:26-29`     文件 + 行号（或行段）
`docs/kb/KB0-conventions.md:26`        单行
```

| 规则 | 为什么 |
|---|---|
| 路径相对**仓根**，从锚点读 | 读者 clone 下来就是同一个路径 |
| 代码按**锚点**读，书按**工作树**读 | 锚点冻结 = 坐标含义冻结；书是活物 |
| 行号必须**逐字核对** | 行在 ≠ 行在说那句话 → `checks.json` 登记词 |
| 仓外原件必须 vendor + 登记 | 读者点不开的坐标不是坐标，是内部暗号 |
| 锚点字符串**单点定义** | 两处各写一份迟早漂；漂了审计照样全绿 |

## 四、裁剪件的规格

**一件**：`crops/裁剪版.md`。

- 各章「可验证主张」与「讲师 90 分钟」两段**原样裁出，一字不改**
  （`tools/verify_crops_verbatim.py` 逐段核对）；
- 编者按语（怎么用 / 授课顺序 / 组合方案）在生成器里，**标明是编者的**；
- 裁剪件里**不许出现**求职口径（简历/求职/投递/岗位要求）——
  那是求职期的产物，开源项目面对的是一类读者。

**为什么只有一版**：读者要的是"一句带锚点、当场可复核的主张"与
"这一章怎么讲"。要两版，就等于要让读者自己判断哪版是给谁的。

## 五、预算

| 项 | 预算 | 说明 |
|---|---|---|
| 概念 | 20' | 讲清这一章的对象与边界 |
| 动手 | 40' | **现场跑真命令**，不得被讲解侵占 |
| 习题复盘 | 30' | 对答案，答案要带坐标 |
| 单章合计 | 90' | 每章的「讲师 90 分钟」表照此排 |

## 六、完成判据

**卷算完成，当且仅当下面每一条都成立**：

| # | 判据 | 谁来判 |
|---|---|---|
| 1 | 坐标审计 0 失败，且行锚断言全部命中 | `tools/audit_coords.py` |
| 2 | 结构体检 0 问题（含锚点字符串一致） | `tools/check_book_structure.py` |
| 3 | 裁剪件与正文逐字一致 | `tools/verify_crops_verbatim.py` |
| 4 | 书中带文件名的数字与实文件一致 | `tools/verify_book_numbers.py` |
| 5 | 脱敏/绝对路径 0 处未清；登记项已披露 | `tools/scan_absolute_paths.py` |
| 6 | 真断链 0 | `tools/check_broken_links.py` |
| 7 | 仓内测试全绿 | `python -m pytest -q` |
| 8 | **清账战役的改动全部记账**：改了什么、为什么改，逐条列在 ch09 §9.6.3 | `git diff <anchor> --stat` + ch09 §9.6.3 |
| 9 | 仓内**跟踪文件**里不再有三档值（主机路径 / ADS NetID / 绝对墙钟） | `python data/probe_pii.py` 第三组全 0 |

第 8 条**曾经**是"本卷没有改动 `src/` `docs/` `tests/` 任何一行"，
那是停机点纪律（ch09 §9.6）的原文。
本卷把它**破了**：查出来的问题比登记的那一处大得多，
只登记不修等于把暴露留在原地（ch09 §9.7.1）。
所以第 8 条改成**"改了必须记账"**——
纪律没变松，只是从"不许改"变成"改要说清"。

第 9 条是清账战役的验收门：它扫的是 `git ls-files` 的结果，
也就是**会被发布出去的那些**（第 8 章 §8.5.2）。

## 七、本卷的登记处

| 文件 | 放什么 |
|---|---|
| `tools/_anchor.py` | 锚点的**唯一**定义 |
| `checks.json` | 行锚断言：这一行必须含哪几个词 |
| `evidence/REGISTRY.json` | 仓外原件的指针 + size + sha256 |
| `known_findings.json` | 查出来的既有问题及其处置（**须在书中披露**；已清偿的项不再豁免扫描） |
| `crops/裁剪版.md` | 裁剪件（生成物，不手改） |

**这五个文件是"本卷承认自己有多少不确定性"的地方。**

`known_findings.json` 的语义在本卷里变过一次：
它原本记的是"**查出来但不修改**"的既有问题；
清账战役之后，它记的是"**查出来了，然后做了什么**"——
状态写着 `cleared` 的登记项，**不再给扫描豁免**：
一旦那个值重新出现在仓里，扫描门必须判失败，
而不是因为"它已经登记过了"就放过。
一个不承认自己可能错的门禁，和一个没有门禁的仓，
在读者眼里是同一种东西。
