# axiscope · 电子书（与 axiscope 代码仓同仓）

> 这是一本讲**怎么读一个工程仓**的书——更准确地说，
> 讲的是**怎么让每个技术主张都能被第三方当场核验**。
> 2026-10-24 起，电子书与 `axiscope` 的代码**同仓**：
> 一个 clone 就能拿到「书 + 一个能跑的案例仓」。
>
> **判断标准不是"哪本好看"，是"哪本的坐标能在这份代码里当场复核"。**
> 本卷的全部坐标都锚在 `axiscope@0bf4ad4`，
> 也就是**本仓自己的某一次提交**上——读者手里没有它，坐标就只剩作者能核，
> 而"当场可核"正是这本书要证伪的那件事。

## 二、坐标怎么用

本书里每一处事实都长这样：

```
`docs/kb/KB0-conventions.md:26-29`
```

含义是：斯图加特大学那批数据集的文件，在**锚点 commit `0bf4ad4`** 的
`docs/kb/KB0-conventions.md` 的**第 26 到 29 行**。

**为什么用行号**：本仓的 Wiki 一开始是**故意不用行号**的
（行号会随增行漂移）。但那是在**没有锚点**的前提下。
项目 2026-10-22 收了尾、进了停机点，**锚点把行号冻住了**——
于是行号同时拿到了两个优点：精确（能指到某一句），且可复核。

**三步复核**：

```powershell
cd axiscope
python book/tools/audit_coords.py        # 解析全部坐标，打印被引行原文
python book/tools/locate.py "看不见"      # 反查：这句话在哪一行
python book/tools/check_book_structure.py # 逐章必备件 + 锚点串一致性
```

第一条会告诉你哪些坐标**指错了行**；
第二条让你能**从一句话反查它的行号**——它也是这本书的写作工具。

## 三、门禁

| 门禁 | 判什么 |
|---|---|
| `audit_coords.py` | 坐标解析 + **行锚断言**（行在不在、那行在不在说那句话） |
| `check_book_structure.py` | 逐章必备件 + 锚点字符串与 `_anchor.py` 逐字一致 |
| `verify_crops_verbatim.py` | 裁剪件与正文**逐字**一致 |
| `verify_book_numbers.py` | 书中带文件名的数字与实文件一致 |
| `scan_absolute_paths.py` | 脱敏标识值 / 绝对路径 / 家目录；登记项**未披露即失败** |
| `check_broken_links.py` | 断链分八类，**只有真断链判失败** |

**当前实测**（2026-10-24）：

```
坐标审计 743 引用 ｜ 743 可解析 ｜ 0 失败 ｜ 行锚断言核对 365
结构体检 9/9 章 ｜ 问题章数 0
裁剪件 18 段逐字命中 ｜ 不一致 0
断链 真断链 0
脱敏扫描 未清 0 处
```

CI 里 `book` 作业会跑这六道门（`fetch-depth: 0` 是硬要求：
坐标审计要按**锚点 commit** 读源文件，浅克隆里没有那个 commit）。

## 四、这卷书不做什么

- 不做使用手册——没有"如何安装、如何调用"的操作序列（那在 `docs/wiki/07-run-guide.md`）；
- 不做规格书——规格书在 `docs/contracts/` 里，那七份契约写得比本书细；
- 不做宣传材料——第 7 章会告诉你它当前的 Top-1 命中是 **0**，
  以及那为什么**不是**一件可耻的事；
- **不改仓内任何一行代码或文档**——本卷是**新战役**，不是叠加
  （见第 9 章 §9.6）。

## 五、一句题词

> 录下来的波形就是闭环反馈的完整记录。
> ——`docs/DECISION-2026-10-19-方向裁决.md:21`

这句话是 axiscope 全部工作的**合法性根基**（第 1 章 §1.2 整章讲它）。
它同时也是这本书的写作原则：

**你录下来的东西，就是你手上的全部证据。
别去补，别去猜，别去修饰——把它按原样摆出来，让别人自己看。**
